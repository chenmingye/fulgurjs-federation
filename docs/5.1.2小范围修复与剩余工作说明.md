## 本轮修改

| 项目 | 修改与验证方式 |
| --- | --- |
| hook 重载旧数据 | reload 开始时清空 data/error，进入 loading；失败后仅保留 error。新增回归从成功数据开始，再让下一次请求真实拒绝 |
| 卸载期间的 reload | effect cleanup 作废请求代次；active 标记阻止卸载后新请求和结果写入。测试直接记录状态 setter，而非观察 React 忽略更新后的界面 |

## 后续工作 A：类型上下文识别（仍需修复）

文件：`packages/plugin/src/dts.ts`，`hostPathsCovers()`。

5.1.1 虽然改为解析 JSONC 并排除了 `tsconfig.node.json`，仍然扫描其他所有 tsconfig。复核构造如下同目录配置：

```jsonc
// tsconfig.json：应用上下文没有 r 的 paths
{ "compilerOptions": {} }
```

```jsonc
// tsconfig.test.json：无关测试上下文有 paths
{ "compilerOptions": { "paths": { "r/*": ["./unrelated-test-types/*"] } } }
```

当前函数仍返回 true，导致生成器可能压掉应用导入所需的 ambient 声明。只排除另一个固定文件名不是完整修复。

执行要求：

1. 先建立实际应用 tsconfig 与无关测试 tsconfig 并存的回归，真实生成输出，再使用应用配置编译导入。
2. 明确如何识别应用 TS 上下文，包括 solution references、extends、只有 tsconfig.typecheck.json 的工程。不能一份配置命中就全局判定。
3. paths 的相对目标和 baseUrl 按有效配置语义解析，保留声明位置；不要只把 paths 对象拿出来后以子配置目录计算父配置路径。
4. 无法确定时给出明确诊断及不会静默破坏导入的处理，不静默改用户 tsconfig，不全部改成 any 规避精确轨。
5. 修复后真实验证合法 props、错误 props、具名函数参数、精确→降级→恢复，保留默认轨与 shim 的既有公开合同。
