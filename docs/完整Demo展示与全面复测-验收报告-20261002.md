## 2. 发现并修复的插件缺陷

### 2.1 已修复（随 5.4.2 发布）

1. **多远程宿主 react-refresh preamble 错源**（MFU-001 "can't detect preamble"，JeecgBoot-A 实抓）
   - 现象：Vue 宿主同时挂 Vue 子应用与 React 子应用时，React 远程模块拒绝求值。
   - 根因：发布脚本静态 import「首个 http dev 远程」的 /@react-refresh，错源（Vue 远程）MIME 失败 → 标志未设。
   - 修复：标志同步先设 + 动态 import 容错 + shim 自举兜底（`src/index.ts`、`src/virtual.ts`）。
   - 回归：`tests/react-refresh-preamble.test.ts` 3 例（含多远程宿主用例）。
   - 实证：修复前 MFU-001 占位（截图）；修复后生产/开发 A 套 React-C 完整挂载。
2. **`BridgeHostRouting` 类型未从 `/bridge/router/*` 导出**（README §8.3 与发布包 d.ts 不符，场景 F 实测）
   - 修复：两路由入口 re-export + 导出面守卫用例（`tests/exports.test.ts`）。

### 2.2 定性登记（不随本版修复）

3. **Vite 8（rolldown）codegen 组合缺陷**：插件 TLA 门面参与大型应用 chunk 合并时，应用 async init 丢 `async` 标记 → `SyntaxError: Unexpected reserved word`（JeecgBoot 实测；minify/target/manualChunks 变体与裸基线对照排除其他变量）。**规避**：该形态应用生产构建用 Vite 5–7；Jeecg 演示实例已切 vite6 构建并全链验收通过。开发态不受影响。
4. **React 宿主 useBlocker 拦截窗口 × Vue 子应用 go(-1) 竞态**：宿主 blocker 阻断 POP 时 Vue 子应用路由同步可产生 2 条 MFU-033 诊断（UI/位置/挂载计数最终一致，无功能破坏；场景 F README 记录复现步骤）。拟后续版本降噪。
