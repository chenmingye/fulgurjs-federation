## 0. 立场：这是一款新插件，不是迁移补丁

用户明确要求（2026-09-14）：

> 「不需要用什么 iframe 兜底，这是在弄一个新的插件，兜什么底。你要测试这个插件完全可用，
> 要把它打磨到完全可用的程度。像你现在这样，用了页面级的全是报错，到处都不对的，这怎么行呢？」

**据此确立三条不可动摇的前提：**

1. **禁止任何兜底/降级路径。** 不允许 iframe 兜底、不允许"联邦失败就静默回退旧通道"、
   不允许 `try/catch` 后假装正常。插件不可用时**必须显式报错**。
   - 事实依据：本项目 prod 环境曾出现 `MFU-008 unknown remote` 真缺陷，**被 iframe 兜底静默吃掉**——
     页面照常显示内容、截图一切正常，是读 console 才发现的。**兜底路径 = 缺陷掩护器**，
     它让"看起来没问题"和"真的没问题"脱钩。这是必须删掉兜底的最硬理由。
2. **失败一律归结到插件自身去解决。** 不得以「这是第三方库限制（avue 只有 UMD）」
   「这是原项目的历史写法」为由把问题挂起来。真实世界的项目就在用 UMD-only 依赖，
   插件必须支持；插件支持不了，就是插件的缺陷。
3. **本项目的真实工程（testbed）就是插件的验收场。** 27 个页面里的每个功能点都要真实可用，
   而不是"路由能打开"。

## 1. 硬性指标（不可协商的验收门槛）

> 全部指标**必须由 e2e 脚本自动断言**（不靠肉眼、不靠"我觉得没问题"），每项给出断言方式。
> 任一指标不达标 = 插件未成型，不允许进入下一阶段。

| 编号 | 硬性指标 | 断言方式（自动化） |
|------|----------|-------------------|
| **H1** | **零页面级报错**：27 页在 dev 与 prod 下，`console.error` = 0、`pageerror` = 0、失败请求（4xx/5xx）= 0 | page.on('console'/'pageerror'/'response') 收集断言全空 |

### 2.2 🔴 阻断级缺陷（不修完不算成型）

**D1：创建流程 / 修改流程页表单完全不显示**
- 现象：表单容器 `display: none`；页内 17 个输入框**全部高度 0**；`form` 元素 `0×0`；截图仅页签+保存按钮、下方全白。
- 根因（已定位到行）：`demo-bpm/src/views/bpm/model/form/index.vue:133`
  `const currentStep = ref(-1) // -1：一开始全部不展示，等数据初始化完成`，
  仅当 `initData()` 跑完才置 0。**联邦环境下 `initData()` 未跑完**（无 pageerror、无失败接口 → 中断或挂起）。
  四个步骤块 `v-if="currentStep===0/1/2"` + `v-show="currentStep===3"`，-1 时四块全不渲染，与实测 DOM 完全吻合。
- 列表点「新建模型」与直链两种入口结果一致 → 非参数问题。
- **验收**：两页表单字段可见可填；填完保存成功、列表数据变化；dev+prod 双环境截图 + 零报错（H1）。

**D2：lowcode 6 页内容区空白**
- 页面：表单设计 / 报表设计 / 图形报表设计 / 模块设计 / 报表测试 / 外部表单。
- 现象：路由与页签正常、接口零失败，内容区空白。
  - dev：`Cannot destructure property 'node' of 'undefined'`、`resolveComponent can only be used in render() or setup()`
  - prod：`TypeError: p.default.extend is not a function`（定位在 lowcode 产物 `assets/domUtils-*.js`，dayjs/element-plus 的 CJS interop 处）
- **定性修正**：不再记作「avue 只有 UMD 的限制」（那是把问题推给第三方）。
  **prod 的报错形态（rollup 产物中 CJS default interop 破）本身就指向插件侧的 CJS/UMD 处理缺陷**，
  且插件对真实工程里 UMD-only 依赖**必须支持**。→ **按插件缺陷处理，必须修到根因。**
- **验收**：6 页在联邦通道下**功能可用**（点得动、存得下、图能出），dev+prod 双环境零报错（H1）。
  **不接受 iframe、不接受"仅 dev 限制"、不接受降级。**

## 4. 执行计划（按序，用户下令后执行）

> 原则：**先能用（H1-H6），再能装（H7），最后好发布（H8-H9）**。每项完成后更新本文档状态 + git 提交推送。

### P0-1 修 D1：模型创建/修改页表单不显示

- **做什么**：定位 `initData()` 在联邦环境下为何未跑完 → 修根因。
- **可能的落点**（按概率）：① `initData()` 内某 `await` 永不 settle（子应用 API/字典/分类下拉）；
  ② 新增分支的 `userStore.getUser.id`（`index.vue:236` 附近）在联邦下 user store 未就绪而抛错被吞；
  ③ `federatedBoot` 对该页未生效（权限/字典 store 缺失）。
- **方法**：`initData()` 每个 await 前后加临时日志，dev 实测定位中断点；在乾坤侧用真实入口做对照，
  **定性是联邦回归还是原项目既有问题**。
- **验收**：H4 该项通过 + H1 零报错 + dev/prod 双截图。

### P0-2 修 D2：lowcode 6 页在联邦通道下可用（按插件缺陷修）

- **做什么**：两件事分开查——
  1. **dev**：avue（UMD-only）预构建内联本地 vue → 双实例。方向：让插件支持 UMD-only/CJS-only 依赖
     （不再依赖"预构建后无法改写"这一既有限制）；可选实现：插件在 config 期生成/dep 转换 ESM 入口、
     或对优化产物做门面改写、或 `optimizeDeps.exclude` + 插件侧 UMD→ESM 转换。
  2. **prod**：`p.default.extend is not a function` 的 CJS default interop 破损 → 定位是插件改写
     哪一步引入的（门面改写 vs commonjs 转换顺序）并修掉。
- **禁止**：iframe 兜底、标记"仅 dev 限制"、把原因归给 avue/上游。
- **验收**：6 页功能可用（可交互、可保存、图表可渲染）+ H1 零报错 + dev/prod 双截图。
- **附带价值**：修好后插件对"只发 UMD 的依赖"这类真实场景即可用，属能力升级。

### P0-3 删除全部兜底/降级路径（H3）

- **做什么**：删除 testbed 内联邦失败回退 iframe 的分支（`detail/index.vue` 情况二/情况三的
  `v-else-if="FormComponentUrl"`）、以及任何静默降级/吞异常写法。失败必须显式报错。
- **验收**：静态检查清单为空 + 人工审计报告写入 docs；删后核心链路仍可用（断网/杀 remote 时显式报错）。

### P0-4 21 页功能级实测（H4/H5/H6，工作量最大）

- **做什么**：逐页逐功能点建 e2e（数据驱动、真实数据、真实入口），覆盖：
  列表渲染/分页/排序/搜索/高级筛选 → 新增弹窗（打开/校验/保存/取消）→ 编辑（回显/保存）→

| `e2e/probe-depth2.mjs` | 功能深度探针：正确选择器（el-table/jeecg-layout-content）+ 加载态卡死检测 + 失败接口 |
| `e2e/probe-func.mjs` / `probe-func2.mjs` | 真实入口（列表点按钮）/弹窗/搜索真过滤/祖先链尺寸诊断 |
| `e2e/amis-dev-verify.mjs` | AMIS 表单联邦渲染验证（dev/prod 参数化） |
| `e2e/amis-seed3.mjs` + `amis-start.mjs` | 造 AMIS 流程全链路测试数据 |

**工具设计约定（教训）**：判据必须落到**功能元素**——数据行数、可见输入框数、弹窗是否打开、
提交后数据是否变化；**禁止**用整页文本长度这类会被侧边栏撑满的弱判据
（本轮就是它把 D1 误判为"通过"）。

## 6. 一句话现状

插件内核扎实（单测 86/86、Vite 5→8 三版本 fixtures e2e 全绿、双向联邦可用），
但**离"能用"还差**：页面集功能级实测（2 个阻断缺陷待修）、零兜底化改造、
装后可用性（H7）、CI 与边界交代。**H1~H9 全部达标之日，才可称"插件成型"。**
