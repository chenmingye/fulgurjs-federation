## 0. 立场：这是一款新插件，不是迁移补丁

用户明确要求（2026-09-14）：

> 「不需要用什么 iframe 兜底，这是在弄一个新的插件，兜什么底。你要测试这个插件完全可用，
> 要把它打磨到完全可用的程度。像你现在这样，用了页面级的全是报错，到处都不对的，这怎么行呢？」

**据此确立三条不可动摇的前提：**

1. **禁止任何兜底/降级路径。** 不允许 iframe 兜底、不允许"联邦失败就静默回退旧通道"、
   不允许 `try/catch` 后假装正常。插件不可用时**必须显式报错**。
   - 事实依据：本项目 prod 环境曾出现 `MFU-008 unknown remote` 真缺陷，**被 iframe 兜底静默吃掉**——
     页面照常显示内容、截图一切正常，是读 console 才发现的。**兜底路径 = 缺陷掩护器**，
     它让"看起来没问题"和"真的没问题"脱钩。这是必须删掉兜底的最硬理由。
2. **失败一律归结到插件自身去解决。** 不得以「这是第三方库限制（avue 只有 UMD）」
   「这是原项目的历史写法」为由把问题挂起来。真实世界的项目就在用 UMD-only 依赖，
   插件必须支持；插件支持不了，就是插件的缺陷。
3. **本项目的真实工程（testbed）就是插件的验收场。** 27 个页面里的每个功能点都要真实可用，
   而不是"路由能打开"。

## 1. 硬性指标（不可协商的验收门槛）

> 全部指标**必须由 e2e 脚本自动断言**（不靠肉眼、不靠"我觉得没问题"），每项给出断言方式。
> 任一指标不达标 = 插件未成型，不允许进入下一阶段。

| 编号 | 硬性指标 | 断言方式（自动化） |
|------|----------|-------------------|
| **H1** | **零页面级报错**：27 页在 dev 与 prod 下，`console.error` = 0、`pageerror` = 0、失败请求（4xx/5xx）= 0 | page.on('console'/'pageerror'/'response') 收集断言全空 |
| **H2** | **零 iframe**：跨应用页面与弹窗一律联邦直渲染，`iframe` 数 = 0（含弹窗打开态） | `page.locator('iframe').count() === 0` |
| **H3** | **零兜底路径**：代码中不存在联邦失败的静默回退分支（iframe 回退、静默降级、吞异常） | 静态检查：`grep -rn "<iframe\|v-else-if=\"FormComponentUrl\|catch" 清单复核` + 人工审计报告 |
| **H4** | **功能点 100% 可用**：逐页功能点清单（第 2 章）每条通过，**含全部写操作闭环**（新增保存/编辑保存/删除/发布/恢复/取消/导入导出/提交审批）。**每一个列表页、每一个功能都必须与乾坤原版一模一样可用**——逐页逐功能对照，不接受"差不多""能用就行" | 每功能点一条 e2e 用例，断言"操作后数据真的变了"（列表行数/字段值/状态）；并与原版逐项对照 |
| **H5** | **双环境一致**：dev 与 prod 行为逐条一致（同样的功能点、同样的断言、**同样的截图套数**） | 同一脚本 `VBASE` 切环境跑两遍，结果 JSON 逐条 diff；两套截图逐张对照 |
| **H6** | **与迁移前一致**：每个功能点与乾坤基线行为一致（动作页需先补基线），列表页/弹窗/交互结果逐项比对，**不一致即不合格** | 四格矩阵：迁移前/后 × dev/prod，逐页逐弹窗截图对照 |
| **H7** | **装了就能跑**：`npm pack` → 干净空项目安装 → 按 README 三步跑通 dev 起服务 + prod 构建部署 | 脚本化：临时目录装 tarball + 官方模板 + 跑通 |
| **H8** | **可回归**：一条命令跑完全部单测 + e2e 全绿，且 CI 每次推送自动跑 | 根 `pnpm test` 退出码 0；GitHub Actions 绿灯 |
| **H9** | **出错能懂**：任意失败场景都有错误码 + 可执行修复建议，无"静默失败" | 故障注入用例：杀 remote / 改错配置 / 版本不满足，断言错误码与文案 |
| **H10** | **证据完备（截图即验收，无截图 = 未测）**：每个功能点闭环**必须带上截图**，且 ① 覆盖闭环的**每一个步骤**（操作前 → 弹窗打开 → 填写/选择 → 提交 → 提交后结果与数据变化）；② **每一个弹窗单独截图**（新增/编辑/详情/删除二次确认/导入导出对话框，含空态与校验报错态）；③ **每一个列表页单独截图**（查询条件区 + 表格 + 分页齐全）；④ **开发环境与生产环境各一整套**，两套逐张对照；⑤ 截图必须能看出所在页面与所处步骤 | 断言：清单中每个功能点的每个步骤都有对应截图文件且真实存在于磁盘；脚本按命名规范产出，缺一张即判失败（规范见 §1.1） |

### 2.2 🔴 阻断级缺陷

**D1：创建流程 / 修改流程页表单不显示 —— ✅ 已结案（2026-09-15）：非插件缺陷**
- **根因（证据链完整）**：本地后台 `/demo/system/dept/simple-list` 接口**稳定耗时 ~13s**
  （curl 带 token 三连测 12.7/13.1/13.0s；user/simple-list 3.4s）。页面按原版设计
  `currentStep=ref(-1)` 等全部数据到齐才显示，四个请求串行合计 ~15-18s → 此前 12s 等待的探针
  全部拍到"表单区空白"。`initData()` 无中断、无异常、无失败请求（[D1] 临时日志逐 await 定位，
  前三个接口全部成功，只有 dept 慢）。
- **乾坤对照定性**：8661 基线原部署反代指向旧后台 localhost（该接口快、数据少），造成
  "原版 3s vs 联邦 18s" 假差异；将 8661 的 `/demo` proxy_pass 对齐到本地 8085 后实测，
  **原版同后台也要 15s 才出表单** → 行为与联邦完全一致。**联邦通道零嫌疑。**
- **验收闭环（e2e/d1-closure.mjs，条件轮询非固定等待）**：dev/prod/qiankun 三环境各自
  新增模型（填标识/名称/分类→保存→"新建成功"→列表分组计数 +1、新名可查）与修改模型
  （回显正确→改分类→保存→"修改成功"→分组计数变化）全部通过；
  console.error=0、pageerror=0、失败请求=0、iframe=0。

**D2：lowcode 6 页内容区空白 —— ✅ 已结案（2026-09-15）：插件两级缺陷修复，dev+prod 六页可用**

  1. **prod：dayjs→esm 别名引发双重 interop**。阶段1为绕 dev 裸 CJS 服务问题给 lowcode/bpm

     6 页模块求值即崩。证据链：CDP 异常暂停帧内求值（`uo` 为包装函数、`oo.extend` 存在于产物）；
     原版产物为单层 interop（`r4(Ff)` 直取模块对象）。
  2. **dev：CJS/UMD 依赖裸源码 serve**。为防双 vue 把 element-plus/avue/dayjs 移出预构建后，
     CJS 文件裸服务即崩（`Cannot destructure property 'node'` 等）。
- **插件修复（能力升级，非 testbed 补丁）**：
  1. **撤销 dayjs 别名**（testbed 配置回原版语义），element-plus/@element-plus/icons-vue/dayjs 回归预构建。
  2. **新增 optimizeDeps shared 外部化**（serve + exposes + devSharedSelf 自动启用）：注入 esbuild
     resolver，把预构建产物内对 shared 键的导入改道到 re-export 桩 → 协商门面
     （`virtual:unifed-shared-ns:<key>`，loadShare 协商 + CJS 导出全量枚举 + vue-demi 兼容导出补齐），
     预构建不再内联本地 vue。esbuild 三条约束逐一踩平：entry point 不可 external（入口解析放行）、
     ESM 输出不支持 require(external)（改道 bundled 桩把门面 URL 提升为 chunk 顶部静态 import）、
     ESM 命名导入缺名即致命（导出清单按本机包 CJS 入口枚举 + vue-demi 兼容名）。
  3. **新增 build 期 CJS require(shared) 重定向**（`cjsRequireRewrite`）：赶在 vite:commonjs 转换前把
     `require("vue")` 重写为 `require("virtual:unifed-cjs-ns:vue")` 垫片（保持 require 形态，

     垫片做 CJS→ESM interop。修复 avue UMD（require("vue")/require("element-plus") 外部依赖）在
