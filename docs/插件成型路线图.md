## 0. 先正面回答质询：我测过没有？

**没有。我此前测的是「页面能不能打开、路由能不能落」，不是「功能能不能用」。** 这两件事差别很大，而且我有明确的反证：

- 我的 27 页矩阵脚本判据是「路由可达 + 关键文本 + 无 pageerror + iframe=0」，其中"渲染 ok"用的是**整页 body 文本长度 > 200 字符**——侧边栏菜单文字就把这个阈值撑满了。结果就是：
- **「创建流程 / 修改流程」两页被我判为 ✅ 通过，实际上表单主体完全不显示（页面不可用）**。
  深挖证据：表单容器 `div.mx-auto.w-700px` 计算样式 `display: none`；页内 17 个输入框**全部高度 0**；
  `form` 元素 `getBoundingClientRect()` = `0×0`；截图只有页签 + 保存按钮、下方全白。
- 根因已定位到代码：`demo-bpm/src/views/bpm/model/form/index.vue:133`
  `const currentStep = ref(-1) // -1 用于：一开始全部不展示，等当前页面数据初始化完成`，
  只有 `initData()` 跑完才 `currentStep.value = 0`。也就是 **`initData()` 在联邦环境下没有跑完**
  （页面无 pageerror、无失败接口，说明是中断/挂起而非报错）→ 整页内容永远隐藏。
  四个 step 用了 `v-if="currentStep===0/1/2"` + `v-show="currentStep===3"`，currentStep=-1 时四块全不渲染，与实测 DOM 完全吻合。

**这不是"顺手发现的小瑕疵"，而是说明：在真正逐功能实测之前，本项目的"迁移已完成"结论是不成立的。**
本路线图把"逐功能实测"定为最高优先级。

## 2. 插件产品化缺口：什么叫"正常的、能用的插件"

我先把标准定出来（第 2 章 = 标准，第 3 章 = 怎么做）。

### 2.1 标准一：装了能跑（3 分钟上手无坑）

当前状态与缺口：

| 项 | 现状 | 缺口 |
|---|------|------|
| npm 包内容 | `npm pack` = **5 个文件 / 40.4 kB**（3 个 dist + package.json） | 🔴 **包内没有 README**（README 在仓库根，未随包发布）→ npm 页面空白 |
| 包内 LICENSE | 无 | 🔴 缺（package.json 声明 MIT 但无文件） |

## 3. 执行计划（按序，用户下令后逐项执行）

> 原则：**先"能用"，再"好装"，最后"好看"**。每项完成后更新本文档状态 + git 提交推送。

### P0-1 修复 D1：模型创建/修改页表单不显示（🔴 最高优先）

- **做什么**：定位 `initData()` 在联邦环境下为何未跑完 → 修复。可能的落点（按概率）：
  1. `initData()` 内某个 `await` 永不 settle（如子应用 API 请求、字典/分类下拉加载）；
  2. 新增分支里的 `userStore.getUser.id`（`index.vue:236` 附近）在联邦下 user store 未就绪而抛错被吞；
  3. `federatedBoot` 对该页未生效（权限/字典 store 缺失）。
- **方法**：给 `initData()` 每个 await 前后加临时日志（dev server 实测），定位中断点；对照乾坤侧真实入口行为。
- **验收**：列表点「新建模型」/「修改」→ 表单字段**可见可填**；填完保存成功、列表出现新模型；dev+prod 双环境截图。
- **顺带**：在 8661 乾坤侧找到真实入口做一次对照，**定性是联邦回归还是原项目既有问题**。

### P0-2 21 页功能级实测（🔴 最高优先，工作量最大）

- **做什么**：为每个页面的**每个用户可见功能点**建一条 e2e 用例（数据驱动 + 真实数据），覆盖：
  列表渲染/分页/排序/搜索/高级筛选 → 新增弹窗（打开/校验/保存/取消）→ 编辑（回显/保存）→
  删除（二次确认/删除后刷新）→ 导出 → 页面特有动作（发布/恢复/取消/历史/重新发起）。
  审批流：发起→提交→待办出现→批准/驳回→已办出现→详情时间线更新。
- **验收**：21 页功能点清单逐条 ✅；**0 个未测功能点**；失败项要么修掉要么写入 UNRESOLVED 并标注原因；
  产出 `docs/页面功能验收清单.md`（逐功能点 + 证据截图路径）。
- **证据**：每个功能点一张截图（落 `docs/screenshots/migration1-dev/`，已 gitignore）。

### P0-3 发布就绪（🔴）

- **做什么**：
  1. 建 `LICENSE`（MIT 全文），并确保随包发布；
  2. `packages/plugin/README.md`（或在 package.json 配 `files` 带根 README）→ npm 页面不为空；
  3. 补 `repository`/`homepage`/`author`/`bugs`/`keywords`/`engines`；
  4. **pack → 干净项目安装实测**（见 2.1 验收标准），这一段必须真跑一遍；
  5. `docs/manual.html` 内部截图/路径脱敏复核；
  6. `@fulgur` npm scope 注册（**交给你**）。
- **验收**：`npm pack` 产物含 LICENSE+README；干净项目按 README 三步跑通 dev+prod；发布检查清单全勾。

### P1-1 阶段 2：6 处跨应用弹窗联邦化

- **做什么**：按 `FormRouterPage` / `AmisFormRouterPage` 两个已验证先例改造（props 先于装载、iframe 留兜底）。

- **验收**：四格矩阵 27 页四格齐全；108 上核心链路可用；权限差异行为与乾坤一致。
