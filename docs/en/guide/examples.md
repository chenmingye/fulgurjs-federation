# Examples and templates

> This page is an index: choosing, running, and ports for templates/demos. Each project's full documentation (deployment details, capability lists) lives in its own README; it is not duplicated here.

## Five copyable templates (`examples/templates/`)

All use the official npm registry package `@fulgurjs/federation` (exact version + pnpm lockfile; the version is pinned in each template's package.json) and do not depend on this repository's source code. Each template directory is a complete pnpm workspace and **must be copied/created as a whole directory**.

| Template | Combination | Demonstrates |
|---|---|---|
| [vue-vue](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/templates/vue-vue) | Vue host × Vue remote | Remote components/TS modules, lazy route loading, error placeholders with retry, production deployment |
| [react-react](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/templates/react-react) | React host × React remote | remoteComponent / useLoadRemote / ErrorBoundary |
| [vue-host-react-remote](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/templates/vue-host-react-remote) | Vue host × React child app | Cross-framework full sub app bridge |
| [react-host-vue-remote](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/templates/react-host-vue-remote) | React host × Vue child app | The bridge in the other direction |
| [showcase](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/templates/showcase) | Dual hosts × dual remotes | Bidirectional bridge + URL sync + multiple remotes coexisting |

### Getting and running

```bash
# Option 1 (recommended, no repo clone needed): create via CLI
npx @fulgurjs/federation create vue-vue --dir my-federation

# Option 2: copy from the repository and run
cd examples/templates/vue-vue
pnpm install --frozen-lockfile
pnpm dev          # Unified launcher: starts the remote first and probes it, then starts the host
# Open the host address noted in the template README (for vue-vue: http://localhost:5214)
```

Environment: Node ≥ 20 (tested on 24.x), pnpm ≥ 9 (≥ 12 recommended; lockfiles are generated by pnpm 12). Launcher behavior: port pre-check before starting (occupied ports are refused), sequential startup with per-app probing, whole-group exit on any failure with lifecycle supervision, and Ctrl+C cleanup down to grandchild processes. Debug individually: `pnpm run dev:remote` / `pnpm run dev:host` (four entries for showcase).

### Default port table (remote starts before host)

| Template | Remote | Host |
|---|---|---|
| vue-vue | 5213 | 5214 |
| react-react | 5203 | 5204 |
| vue-host-react-remote | react-remote 5303 | vue-host 5314 |
| react-host-vue-remote | vue-remote 5313 | react-host 5304 |
| showcase | vue-remote 5335 / react-remote 5333 | vue-host 5334 / react-host 5336 |

### The fixed checklist for changing ports

`fulgurjs port <app> <new-port>` (run from the template project root) previews/writes all four places at once; when editing by hand **all four must be changed in sync** (missing any one leaves the launcher stuck on the old port):

1. The `--port` in each app's `package.json` `dev` and `preview` scripts (change both);
2. The dev addresses in the host `fulgurjs.config.ts` `remotes`;
3. That app's `port` in the root `scripts/dev.config.json` (**must change**: the launcher's pre-check and probing read this);
4. The port table at the top of the template README.

Production deployment addresses (`prod`) are site paths, unrelated to dev ports; changing ports does not touch them. Command details: [CLI reference · port](../reference/cli.md#fulgurjs-port).

## Feature demos (`examples/demos/`)

Capability demos beyond the templates, also independently downloadable and runnable (npm projects). Scenario locations, ports, and startup order are all registered in [examples/scenarios.json](https://github.com/chenmingye/fulgurjs-federation/blob/master/examples/scenarios.json):

| Scenario | Directory | Covers |
|---|---|---|
| Shared dependencies and runtime | [demos/shared](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/demos/shared) | singleton/version negotiation/strictVersion/aliases/eager/fallback, dynamic registration, preloading, runtime plugin hooks, AppContext live inspection |
| React 18/19 isolation and recovery | [demos/react-versions](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/demos/react-versions) | React 19 host embedding React 18; independent scopes, async shared arbitration, strict version rejection and reload after alignment |
| Page tables, types, and CLI | [demos/pages-cli](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/demos/pages-cli) | definePages/createHostPages/remoteSchema/requireAppContext; all commands: init/explain/check-pages/doctor |
| Error recovery | [demos/errors](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/demos/errors) | Unreachable remote/broken entry/timeout/version conflict/illegal bridge contract/setup and unmount exceptions — isolated fault injection, demonstrating error codes and recovery paths one by one |
| Same-framework full sub app bridge | [demos/same-frame](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/demos/same-frame) | Vue wrapping Vue, React wrapping React — comparing "component-level federation vs app-level bridge" |
| Jeecg integration | [integrations/jeecg](https://github.com/chenmingye/fulgurjs-federation/tree/master/examples/integrations/jeecg) | JeecgBoot v3.9.5 A embedding B nested, Jeecg↔React bidirectional, controlled three-level nesting A→B→C |

Repository-root management commands (no need to install the repo root dependencies first):

```bash
node examples/scripts/check-catalog.mjs          # Verify scenarios, workspace members, and lockfiles
node examples/scripts/check-env.mjs              # Show package manager, install, and port status
node examples/portal/server.mjs                  # Showcase portal: http://localhost:5390
node examples/scripts/start-demo.mjs --scenario vue-basic   # --scenario repeatable; --all for everything
node examples/scripts/build-demo.mjs --scenario vue-basic
node examples/scripts/stop-demo.mjs --scenario vue-basic
```

## Suggested learning path

1. **Run a same-framework template first** (vue-vue or react-react): compare with [loading components and modules](components-and-modules.md) to study remoteComponent usage on the host home page;
2. **Shared negotiation / version isolation**: run demos/shared and demos/react-versions, compare with [shared dependencies](sharing.md);
3. **Cross-framework embedding**: run a bridge template or showcase, compare with [sub app bridge](app-bridge.md) and [URL sync](url-sync.md) (try deep-link refresh and back/forward in showcase);
4. **Per-page pages and the CLI**: run demos/pages-cli, compare with [remote page integration](remote-pages.md) and the [CLI reference](../reference/cli.md);
5. **Error handling**: run demos/errors, compare with the [error code table](../reference/errors.md) and the [troubleshooting index](../troubleshooting/README.md).

The npm package ships only the five templates in `examples/templates/`; feature demos, the Jeecg integration, and the portal come from the GitHub repository.
