# 插件改进项评估与排期建议（2026-09-16）

> 来源：品牌清理收尾续作交接「三、未完成清单 D」——本轮实测暴露的易用性问题。
> 性质：改进建议，非本轮必做。每项含问题、根因、方案、可行性、排期建议。

---

## D.1 远程 SFC 静态导入 `virtual:fulgur-runtime` 的 dev 检测

**问题**：远程应用的页面 SFC 若静态 `import 'virtual:fulgur-runtime'`，dev 下渲染上下文被破坏
（resolveComponent / withDirectives / "Missing ref owner" 三件套告警，内容区静默空白），
插件侧无任何报错。本轮实测排障耗时约 40 分钟（二分定位）。

**根因**：虚拟模块由远程 dev server 求值，会在远程模块图内实例化一份独立 runtime，
SFC 的渲染 setup 绑定到错误的应用上下文。正确姿势是 `globalThis.__FULGUR_RUNTIME__`
（宿主已初始化的单例，见 manual/迁移指南与 bpm `detail/index.vue` 内注释）。

**方案**：插件 transform 阶段（`devRewriteAll` / `transformModule` 通路，dev-only）检测
"有 exposes 的远程应用源码"里出现 `virtual:fulgur-runtime` 静态导入时 `this.warn` 显式告警，
文案给出替换写法；可再提供 opt-in 自动改写为 globalThis 桩（默认不启用，避免语义意外）。

**可行性**：高——transform 已扫描 import（`transform.ts` 的 runtimeSpec 改写同通路），加一个
检测分支成本极小。误报面：远程应用自身入口由插件生成、不经用户源码，用户源码里出现该导入
基本必是误用。

**排期建议**：短期，v0.3.0。低成本消灭一类 40 分钟级排障，性价比最高。

## D.2 带参路由 expose 键冲突告警

**问题**：宿主侧路由表（如 admin `fulgurPages.ts`）从带参路由推导 spec 时剥离 `:param`
（例：`model/:type/:id` → `pages/bpm/manager/model`），与列表页 expose 键收敛相同时静默错配
——曾实际导致"复制流程"误走"更新"语义（数据风险，见遗留任务交接清单 §2.1 纠偏）。
目前只能靠人工写 `spec` 显式覆盖规避。

**方案**：路由表在插件视野之外（应用侧数据），插件无法直接感知。两条路：
1. 提供 `defineFulgurPages()` 帮助函数（官方 API），构建/启动期做重复 spec、参数剥离收敛检测并告警；
2. 轻量版：文档化"带参路由必须显式 spec"的检查清单 + 在 dev 容器入口对宿主注册的路由参数做运行时探测告警（可行性一般，易误报）。

**可行性**：中——需要新增 API 面（方案 1）或接受文档约束（方案 2）。方案 1 与宿主侧 API
官方化方向一致，但涉及设计决策（路由表 schema 是否收进插件）。

**排期建议**：中期，v0.3.x~v0.4，与宿主侧路由映射 API 官方化一批做。

---

## D.3 `globalThis.__FULGUR_RUNTIME__` 官方化

**问题**：跨源单例目前是内部约定（bpm 详情页消费 admin exposes 必须走它，仅代码注释与
manual 提及）。无版本信息、无稳定性承诺，远程页面作者只能靠口口相传。

**方案**：
1. 文档化为公开契约（manual/迁移指南单列一节："远程页面如何取宿主运行时"）；
2. runtime 加固：挂载时 `Object.freeze` 关键方法面 + 附 `version` 字段（诊断多副本/版本漂移）；
3. 可选：在虚拟模块与 `/fulgur-runtime.js`（独立产物，本次最小宿主页已实测可用）里
   同时导出 `getRuntime()` 等价入口，缓解记忆负担——但远程 SFC 仍以 globalThis 为唯一跨源通道（见 D.1）。

**可行性**：高——本次品牌清理收尾已产出 `dist/runtime.js` 独立构建（esbuild 产物 12.4KB），
最小宿主页（`e2e/nginx/minimal-host.html` + 8662 实测）验证了纯运行时 API 消费路径，
官方化主要是文档 + 少量加固代码。

**排期建议**：短期，v0.3.0 与 D.1 同批（一次文档+一个小版本）。

## 优先级总览

| 项 | 建议 | 理由 |
|---|---|---|
| D.1 静态导入检测 | v0.3.0 | 成本极低，直接消灭最贵的排障场景 |
| D.3 runtime 官方化 | v0.3.0 | 文档为主，独立产物路径已实测 |
| D.2 路由键冲突告警 | v0.3.x~v0.4 | 涉及 API 设计决策，随宿主侧官方化一起 |
