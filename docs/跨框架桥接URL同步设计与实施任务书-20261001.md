# 跨框架桥接 URL 同步：设计与后续实施任务书

> 作者：Jason.chen；编写日期：2026-10-01。
> 状态：**实施中（2026-10-02 起授权实施）**。§1 原型门禁已通过（27/27，两种组合 + hash 变体，证据 testbed/runs/20261002-urlsync-proto/evidence/proto-gate-final.txt），§3 签名自此冻结为正式 API。
> **原型实证的四条关键结论**（实现必须遵守）：
> 1. Vue Router 4 的 `app.use(router)` install 会补发初始导航——子应用初始 memory push 落定前不得 install/mount，否则深链初始位置被 START('/') 覆盖（原型实测复现并修复）。
> 2. React Router 7 data router 的 `router.navigate()` 被 blocker 拦截时**静默返回 void**（dist 源码核实）——端口对子应用发起的导航用「与 useBlocker 同一取消策略预判」（cancelled、URL/历史零副作用）；菜单/POP 等其他来源由树内 useBlocker 真实拦截。declarative 模式（BrowserRouter）无 blocker 能力，如实声明不支持取消。
> 3. 子应用受控路由：React 用 `createMemoryRouter`（订阅+程序化导航+Link 全兼容）；Vue 用 `createRouter({ history: createMemoryHistory() })`，桥接 afterEach→通道请求、通道广播→replace，宿主取消时回滚最后确认位置。
> 4. 挂载 pending 期间换路径：mount 前（含异步初始化后）必须重新读取宿主最新位置并以之为通道初始值；组件卸载/代次失效后异步续体必须中止（Vue onMounted 续体不被框架取消，需 alive 标志）。
> 参考基线：已提交的 `ea33938` / 已发布的 5.3.0 桥接。编写时工作区存在另一轮插件修复改动；本文不以这些尚在修改的代码为已验收基线。执行时重新读取最新源码、版本、修复报告和工作区状态。
> 新增能力建议使用下一个未占用 minor；5.3.x 之后的候选为 5.4.0，实际版本以实施当天 registry、Git tag 和依赖约束为准。

## 0. 功能目的与执行范围

现有 `/bridge` 可将 Vue/React 子应用挂载在宿主页面中，子应用内部使用 memory 路由。内部跳转不自动更新浏览器地址；刷新不能依靠地址恢复子应用内部页面，复制链接通常只能定位到子应用入口。

本功能让宿主 URL 表达当前子应用内部路径，并支持刷新直达、收藏分享、前进后退与宿主菜单跳转。示例：

| 场景 | 宿主逻辑路径 | 子应用逻辑路径 |
|---|---|---|
| 审批列表 | `/approval/tasks` | `/tasks` |
| 审批详情 | `/approval/detail/123?tab=history#comment` | `/detail/123?tab=history#comment` |
| 打开完整链接 | 根据 `/approval/*` 加载审批子应用 | 首次直接进入指定详情 |
| 浏览器后退 | 回到上一条宿主历史记录 | 同步显示对应页面，或随宿主离开该子应用 |

URL 只能恢复路径、查询参数和片段所表达的页面位置；未保存表单、组件内存、滚动位置和业务数据不因本功能自动持久化。

现有 `createHostPages` / 普通远程页面由宿主路由直接管理的能力继续适用。本文新增的是跨 root、跨框架子应用内部路由同步，不把现有宿主深链支持描述为缺失。

### 0.1 v1 支持面

- Vue 宿主 → React 子应用、React 宿主 → Vue 子应用，两种组合均实现和实测。
- 宿主路由统一管理浏览器 URL；子应用使用受桥接协调的内存/受控路由。
- Vue Router 4；React Router 6/7。具体可支持版本在原型与矩阵中验证，不能仅按名称宣称兼容。
- 宿主 history 与 hash 模式。两种模式通过路由适配器转换为统一逻辑路径，不由子应用自行读取 `window.location` 猜模式。
- path、search、hash，push、replace、浏览器前进后退、同应用内菜单跳转、初始深链与根路径重定向。
- 现有不启用 URL 同步的桥接保持默认 memory 行为，不增加路由库强制依赖。

### 0.2 边界

- SSR/RSC、跨浏览器窗口、iframe 与跨 realm 通信不在本轮范围。
- v1 不提供嵌套桥接子应用之间的多级路由代理；一个宿主路由层级挂载一级桥接子应用。
- 不自动继承宿主 Vue provide/inject 或 React Context，不共享两端 Router 实例。
- 不提供未保存表单自动保存、浏览器关闭拦截或跨 root 滚动恢复。
- v1 以宿主导航权限/取消守卫为权威。子应用中独立的异步取消守卫不能假装自动参与宿主导航；需要取消跨 root 导航的业务逻辑注册在宿主侧。子应用本地路由失败的处理见 §5.4。
- TanStack Router、React Router Framework/SSR 模式和其他路由库没有验证前不承诺支持；可通过统一端口扩展。

## 1. 设计决策与原型门禁

以下为推荐技术方案，不把尚未实现的签名写成作者已确认的现行 API。实施方应先做两种组合的最小原型，证明 §4/§5 时序可行，再冻结类型和更新本文；不得为了沿用示意签名而交付错误的历史记录或死循环。

| ID | 推荐决策 | 理由与要求 |
|---|---|---|
| R1 | URL 同步显式开启；默认关闭 | 保持 5.3.x memory 模式、老契约和普通模块消费兼容 |
| R2 | 宿主路由是浏览器历史的唯一写入方 | 子应用不创建自己的 BrowserRouter/createWebHistory，不竞争同一 history |
| R3 | 每个启用实例显式声明 `basePath` | `/approval` 对应子应用 `/`；从宿主逻辑路径中去除前缀 |
| R4 | 路由通过独立控制通道传递 | 不放入 `appProps` 快照，不使用全局 AppContext/event bus 偷传，不以路由变化重挂 root |
| R5 | Vue/React 路由适配器按需入口 | 纯框架入口和不开启同步的项目不增加另一框架或路由库导入 |
| R6 | 导航以宿主提交结果为准 | 子应用请求不能凭 `navigate()` 函数返回就报告成功；支持取消、重定向和迟到结果作废 |
| R7 | 历史记录只增加一次 | 首次深链、宿主通知与前进后退不再 push；内部重定向按 replace 规范化 |

原型至少证明：首次详情深链、子应用 push、宿主 push、一次 back/forward、导航取消、根重定向、挂载 pending 时换路径、卸载后迟到通知。若某一宿主模式不能兑现，修适配器或显式调整待实施支持范围，不能保留空泛的“全模式支持”。

## 2. 路径、前缀与部署规则

### 2.1 统一逻辑位置

```ts
export interface BridgeLocation {
  pathname: string // 以 / 开头；子应用位置为去除 basePath 后的路径
  search: string   // 空串或以 ? 开头；保留编码、重复 query 键
  hash: string     // 空串或以 # 开头
}
```

不要把 search 转成只允许单值的对象再拼回，避免丢重复键、顺序与编码。比较使用规范化后的三部分，不能只比较 pathname；改变查询参数也必须同步。中文、空格、百分号须避免二次 decode/encode。

### 2.2 前缀映射

- `basePath` 使用宿主路由视角的静态绝对路径，例如 `/approval`；v1 不接受空值、根 `/`、query/hash、origin、通配符或参数模板。
- 统一规范化末尾 `/`，按路径段匹配：`/approval` 与 `/approval/...` 命中；`/approval-old` 不命中。
- 宿主路由必须声明相应的后缀匹配：Vue `/approval/:pathMatch(.*)*`、React `/approval/*`。只匹配入口 `/approval` 会导致详情导航卸载子应用。
- 宿主 `/approval` 对应子应用 `/`。是否从 `/` 重定向到 `/tasks` 由子应用路由定义；同步时 replace，不能凭空制造一条额外历史。
- 子应用导航目标是自身范围内的位置；不允许通过 `../`、协议、`//origin` 或编码分隔符逃逸到其他前缀。导航其他宿主菜单通过业务显式宿主能力完成。
- 同时存活的同步实例不得占用相同或重叠前缀；冲突给诊断。普通 memory 小部件可多实例，不受 URL 前缀登记限制。
- 未命中自身前缀时不抢占 URL、不回推默认路径；由宿主路由决定卸载/离页。

### 2.3 Vite base 与路由 base 的区别

部署在 `/erp/`、宿主 Router basename/base 为 `/erp/` 时，适配器拿到的逻辑路径是 `/approval/detail/123`；同步 `basePath` 仍是 `/approval`。浏览器实际地址为 `/erp/approval/detail/123`。禁止重复拼出 `/erp/erp/...`。

远程资源地址、manifest/entry URL、remote 的 Vite base 与宿主路由前缀分别处理；深链永远首先请求宿主站点，不把子应用页面路径发到远程资源服务器。

history 模式的生产服务器需把宿主非资源深链回退到宿主 index.html；静态资源、API、manifest/entry 的真实 404 不能被 HTML 回退掩盖。hash 模式还需验证 `#/approval/detail/123?tab=history#comment` 的逻辑片段解析，不能把第二段 hash 当 origin 或忽略掉。

## 3. 目标 API 草案

### 3.1 宿主：给返回组件增加独立 routing 控制 prop

```ts
export interface BridgeHostRouting {
  basePath: string
  navigation: BridgeHostNavigation
}

export interface BridgeHostNavigation {
  getLocation(): BridgeLocation
  subscribe(listener: (location: BridgeLocation) => void): () => void
  navigate(
    target: BridgeLocation,
    action: 'push' | 'replace',
  ): Promise<BridgeNavigationResult>
  go(delta: number): void
}

export type BridgeNavigationResult =
  | { status: 'committed'; location: BridgeLocation }
  | { status: 'cancelled'; location: BridgeLocation }

// 扩展现有桥接组件 props，不放进 appProps，也不改变 sessionKey 语义。
// routing 省略：沿用原 memory 模式。
// routing 开启：通过导航端口与 basePath 生成当前实例的子应用路由通道。
type BridgeHostProps<P> = {
  appProps?: P
  sessionKey?: string | null
  routing?: BridgeHostRouting
}
```

适配器负责把 Router 的位置、导航结果和订阅转换成上述统一端口。端口表示逻辑路径，不暴露宿主 Router 实例给远程。未知导航异常使用 rejection，取消使用 cancelled，不能把取消当成加载失败。

建议按需入口与命名（原型后冻结）：

```ts
// Vue 宿主：在已有 router 实例上建立稳定端口
import { createVueBridgeNavigation } from '@fulgurjs/federation/bridge/router/vue'
const navigation = createVueBridgeNavigation(router)
const routing = { basePath: '/approval', navigation }
// <RemoteApp :routing="routing" :session-key="loginKey" :app-props="businessProps" />

// React 宿主：必须在 Router 上下文内调用；hook 返回稳定端口
import { useReactBridgeNavigation } from '@fulgurjs/federation/bridge/router/react'
const navigation = useReactBridgeNavigation()
// 将 routing memo 化；不得每次 render 重新登记 Router 监听器
// <RemoteApp routing={{ basePath: '/approval', navigation }} ... />
```

React Router 不同运行模式下 navigate 的返回类型并不相同；实现不得只 `await navigate()` 就声称宿主已提交。需要关联 location 通知、请求编号和实际导航结果；可取消导航的模式必须能明确返回 cancelled。没有取消能力的适配模式如实注明，不声称实现任意 blocker。

### 3.2 子应用：扩展契约控制参数，保留原签名兼容

```ts
export interface BridgeChildRoute {
  getLocation(): BridgeLocation // 子应用逻辑位置；每次读取最新宿主已提交位置
  subscribe(listener: (location: BridgeLocation) => void): () => void
  navigate(
    target: BridgeLocation,
    action: 'push' | 'replace',
  ): Promise<BridgeNavigationResult> // 结果中的 location 也使用子应用坐标
  go(delta: number): void // 委托宿主；不创建第二条独立浏览器历史
}

export interface BridgeMountOptions {
  signal: AbortSignal
  routing?: BridgeChildRoute
}

export interface BridgeApp {
  routing?: { protocol: 1 } // 仅支持同步的契约声明；缺省表示老契约
  mount(
    el: HTMLElement,
    props?: Record<string, unknown>,
    options?: BridgeMountOptions,
  ): void | Promise<void>
  unmount(el: HTMLElement): void
}
```

- 第三个参数用于生命周期/路由控制，不能混入业务 props。未开启 routing 时继续允许老契约和原 `mount(el, props)` 调用。
- 开启 routing 时必须验证契约协议；缺失或不兼容即给出诊断，不允许退回 memory 后假装深链成功。
- `defineBridgeApp` 建议增加显式 `{ routing: true }` 选项与工厂第二参数（提供 signal、routing）。子应用无需直接操纵浏览器 history。
- Vue 初始 memory 导航可能异步；如需扩展工厂为 `VueApp | Promise<VueApp>`，必须在原型中实现完整取消与清理守卫，保持原同步工厂行为。不能为了等待 router 就让 pending 卸载失效。
- React 工厂保持返回 ReactElement；路由支持通过可选包装器在子应用自己的 root 内建立，不能试图读取宿主 React Router Context。

### 3.3 子应用路由接入

Vue 侧建议提供 `connectVueBridgeRouter`：连接子应用自己的 memory router 与 BridgeChildRoute，返回初始化 ready 与 dispose。初始路径应先导航到最新路由，再首提交；订阅、取消信号与监听器由本轮 mount 生命周期管理。未启用同步时使用原 memory 初始化，不写宿主 URL。

React 侧建议提供 `BridgeRouter`：在子应用 root 内建立受控 Router，初始 location 来自通道；Link、useNavigate、replace 和相对导航经适配器向宿主提出请求。不要套一个 BrowserRouter 直接监听相同 window，也不要只在 MemoryRouter.initialEntries 填初始值后忽略后续通知。

适配器要覆盖路由库的实际导航入口，不能仅给出自定义按钮 navigate 而让正常 RouterLink/Link 悄悄脱离同步。子应用相对导航先在自己的路由坐标中解析，然后再加宿主前缀；路由库命名路由对象等特有形式在本地解析，不进入通用端口。

## 4. 生命周期与会话

### 4.1 首次深链

1. 宿主 Router 解析 URL 与权限，命中带后缀的桥接路由。
2. 包装组件完成既有 sessionKey/getContext 校验，加载契约。
3. 在实际 mount 前再次读取当前宿主位置；远程加载期间 URL 可能已从详情 123 变成 456，不能使用工厂创建时的旧快照。
4. 验证前缀与协议，创建按实例和 mount 代次隔离的路由通道。
5. 子应用从指定位置初始化；Vue 等待必要的初始路由准备，React 从目标 location 首次渲染。
6. 首次根提交成功后进入 ready。不得先显示 `/` 默认业务页、发错接口，再补跳详情。

### 4.2 已挂载的路径变化

同一 sessionKey、同一 basePath 内的 path/search/hash 变化更新独立路由通道，保留 root、store 与已装配插件，不重新 loadRemote/mount，也不把“换 key 重建”当作正常 URL 同步。

routing 对象引用重新创建但 navigation 与规范化 basePath 相同，不重挂、不重复订阅。启用/关闭同步、切换端口或 basePath 属于控制配置变化，应按明确的重新绑定/重挂策略执行并测试，不能留下旧前缀的监听器。

### 4.3 换账号、登出、缓存与卸载

- 沿用最终修复版 sessionKey/clearAppContext 规则；路由通道不是第二套鉴权。
- 登出或旧代次作废立即禁用其 navigate/go，清理订阅与前缀登记；旧请求完成后不得改写 URL 或复活子应用。
- 路径中有私有详情 ID 时是否退到登录页/列表由宿主权限流程决定，不能重新登录后无条件恢复前账号页面。
- unmount 失败依旧封锁不确定容器，不借助“路由重试”绕过已修复守卫。
- KeepAlive 缓存中的非当前子应用不能继续回推 URL；应按前缀命中状态暂停路由写入。此处是路由通道状态管理，不新增业务 app 的暂停/恢复生命周期。
- 宿主端口与组件生命周期分别清理：共享端口不能被某个子应用卸载时整体销毁；端口自身由创建它的宿主模块释放。

## 5. 导航、历史记录与异常

### 5.1 子应用 → 宿主

子应用提出目标与 push/replace → 验证当前代次、前缀与目标 → 宿主 Router 执行权限/取消/重定向 → 宿主提交位置 → 广播实际位置 → 子应用确认并渲染。

宿主可能取消或重定向，最终位置不能用请求目标代替。适配器若需要先更新本地 memory，必须在 cancelled/失败时恢复最后已确认位置，并证明不会再次请求宿主；不能留下 URL 与页面不一致的终态。

### 5.2 宿主 → 子应用 / 浏览器前进后退

宿主菜单、地址栏打开、宿主 push/replace、浏览器 pop 都通过宿主端口通知子应用。子应用应用通知时不再 push 宿主，保持一份浏览器历史。

`go(-1)` 可能离开子应用，按宿主实际历史运行；不能用子应用本地栈模拟或在离页后把 URL 拉回。`go` 接受有限整数，校验非法值；不额外制造历史。

### 5.3 循环、并发与重定向

- 每次请求记录实例 ID、mount 代次、请求编号与来源；宿主通知和子应用请求区分来源。
- 已确认同位置导航是 no-op，不重复 push；规范化过程保留 search/hash。
- 每个实例串行管理内部导航请求；已取消/作废的队列项不能后来提交。宿主菜单/POP 等外部导航更新权威位置，未提交的旧内部请求不得覆盖它。
- 必须测试“子应用连续请求 A/B、宿主守卫延迟、随后浏览器后退”这种真实时序。若 Router 已接受旧请求并无法取消，以实际提交事件仲裁，不能谎称请求已取消。
- 根路径与子应用规范化重定向使用 replace；设置有界重定向检测。超过上限给根因与目标链，不能无限循环或静默回入口。
- 不 monkey-patch 全局 history.pushState/replaceState，不篡改另一个 Router 的 history.state。应用自定义 state、滚动标记与 Router key 必须通过宿主正常导航保留。

### 5.4 权限、404 与路由准备失败

宿主守卫负责跨 root 的权限和取消决定。若导航取消，URL、子应用位置、历史记录保持最后确认状态；取消不能自动重试。

子应用普通路由重定向按实际最终位置规范化。v1 不自动协调两端任意异步取消守卫；如子应用自己的守卫拒绝已提交的宿主位置或路由准备失败，必须给出显式路由诊断并阻止错误页面显示，不能声称同步成功。实施方若扩展支持两端守卫，需要原型证明取消时 URL、页面和历史一致并补验收，不用简单 replace 回滚掩盖历史污染。

子应用未知路由由自己的 404 页展示并保留该 URL；宿主未知前缀由宿主 404 处理。刷新恢复的是路由位置，业务接口、详情权限与数据不存在仍按业务正常处理。

## 6. 包接线、依赖和诊断

| 位置 | 实施责任 |
|---|---|
| bridge-core / 契约类型 | 可选协议、mount 控制参数、位置/导航结果类型、前缀与代次管理 |
| bridge-host-vue/react | 独立 routing prop、通道生命周期、同应用内路径更新不重挂 |
| bridge-app-vue/react | 工厂上下文、首路由准备、取消清理与首次提交时序 |
| 新增 router 适配模块 | Vue/React 宿主端口与子应用适配，按需导入，复用同一映射内核 |
| package exports/typesVersions/build | 两个可选路由入口及声明、框架/路由库外置；不扩大普通入口依赖 |
| virtual/transform/gen-runtime-entry | dev 门面、暴露源码改写与正式包壳一致，无第二个 runtime |
| fixtures/examples/e2e | 两种组合、history/hash、子目录部署、深链与守卫用例 |
| README 中英 / DESIGN / CHANGELOG | 当前支持面、启用/关闭、自定义端口与恢复方式、真实版本兼容 |

Router 依赖作为可选 peer 或可选适配入口的明确消费合同处理，版本范围以测试确定。Vue 路由入口不引 React Router，反向亦然；默认 `/bridge`、`/runtime`、`/react` 不静态引入新的路由依赖。

错误码在实施当天检查现有码表后登记，不预占 MFU 编号。至少区分：路由配置/前缀冲突、协议缺失、路由准备/同步失败、重定向循环。使用 FgError 与中文三段式诊断，保留 cause 和 phase；导航取消是正常结果，不伪装网络错误。禁止将 URL 同步失败显示成 ready 并静默丢弃。

不增加配置文件里的第二套路由表；宿主继续使用现有 Router 配置，桥接声明前缀和可选端口即可。诊断记录不包含 token、用户私有数据或整个业务 history.state。

## 7. 验收矩阵（实现时逐项提供证据）

两种跨框架组合均执行；路由成功必须同时断言 URL、子应用内容、root 挂卸次数与历史行为，截图仅作补充。

| ID | 场景 | 通过标准 |
|---|---|---|
| U01 | 默认不启用 | 既有 memory 桥接、旧契约与普通远程页面全部回归；无新路由库强制加载 |
| U02 | 初次详情深链 | 首次即目标详情与参数，不闪默认业务页、不请求错误详情 |
| U03 | 子应用 Link/RouterLink/push | URL 与内容同步，只新增一条历史，root 不重挂 |
| U04 | 子应用 replace/默认重定向 | 替换当前记录，不重复前缀、无额外入口记录 |
| U05 | 宿主菜单同前缀跳转 | 子应用进入指定页面；已挂载 root/store 保留 |
| U06 | 后退与前进 | 列表→详情→后退→前进均对应正确 URL/内容；可正确离开该子应用 |
| U07 | query/hash/编码 | 查询、重复键、中文、空格、百分号与片段真实保留；仅参数变化也更新 |
| U08 | 刷新/收藏/新窗口 | 生产完整链接重新打开直达详情；不会发到远程资源服务器 |
| U09 | 子目录部署 | Vite base、宿主 Router base、bridge basePath 各自正确；资源和深链无重复前缀 |
| U10 | 宿主 hash 模式 | 外层 hash 路由、内层片段、push/replace/pop 与直链均通过 |
| U11 | 取消/重定向 | 宿主取消不改变确认位置/历史；重定向以实际目标为准；无自动重试 |
| U12 | 路由尚未准备时换路径 | 使用 mount 前最新目标，迟到初始化不覆盖新位置 |
| U13 | 快速导航与外部 POP | 延迟守卫、连续请求与 back 交错时最终状态一致，无过期回推 |
| U14 | 登出/换账号 | 旧通道不能写 URL，新代次重新校验权限，无旧账号私有页残留 |
| U15 | 卸载/失败/StrictMode/HMR | 无旧订阅、重复 push 或迟到写入；卸载失败容器仍封锁 |
| U16 | 多实例/缓存 | 正常 memory 多实例保留；同步实例前缀冲突诊断；缓存离页不抢占 URL |
| U17 | 404 与协议违例 | 子应用/宿主各自 404；老契约开启同步给明确错误，不假装成功 |
| U18 | 循环/非法目标/导航异常 | 有限重定向；拒绝越界、非法 go 和失效实例请求，诊断可操作 |
| U19 | 正式包消费 | 两端可选入口、类型、安装、dev/build/生产加载全部使用 registry 精确版本 |
| U20 | 导入图和体积 | 默认入口不加路由依赖；双框架隔离；真实适配模块体积前后值和门禁 |

版本矩阵：Vue 3、React 18/19，Vue Router 4、React Router 6/7 的实际支持组合；Vite 5.1/6/7/8 均执行双向最小 dev/build/生产加载。host history/hash 至少各执行完整 U02—U11 关键链；不要只构建不打开生产页面。

页面内取消用真实宿主守卫或支持 blocker 的路由模式测试，注明具体模式；不使用 mock 的 cancelled 值冒充实际框架行为。10 轮挂卸检查订阅计数与迟到事件，记录 StrictMode 与 HMR 实际结果。

## 8. 实施顺序、发布与完成定义

1. 重新核对实际源码和版本，确认上一轮桥接/Vite 兼容补修的结果；未解决的插件发布门禁不能借新功能跳过。
2. 记录工作区，保护已有改动；建立独立轮次 checkpoint。核查原型所需 Router 版本与 API。
3. 完成 §1 原型门禁，冻结 API、依赖/入口、守卫边界与类型，同步本文，避免实现半途产生两套签名。
4. 先实现位置映射/导航仲裁与负向验证，再接宿主/子应用适配、生命周期、dev 门面和包壳。
5. 增量扩展 fixtures/examples，提供 history、hash、开启、关闭与自定义端口的可运行用法。
6. 执行 build、单元、有效 tsconfig 类型检查、错误码、导入图和体积门禁；候选 tarball 隔离安装并跑 U01—U18、U20 及版本矩阵。
7. 发布前检查有 FAIL/BLOCKED/NOT RUN 时不能宣称通过并发布。解决插件缺陷后按项目流程提交推送、tag、Release、npm 正式发布。
8. registry 精确安装复验 U19 与关键深链/历史链路，核验 provenance、integrity 与实际包内容。
9. Vue 与实际宿主回归覆盖原页面路由、菜单、权限、会话及生产深链。MES 如参与，使用当前已授权的测试副本流程，SVN 永不提交；不把“URL 能打开”替代业务页面验收。
10. 交付 `docs/跨框架桥接URL同步实施验收报告-<日期>.md`，包含完整矩阵、原始证据、最终版本/commit、体积、未解决项、使用示例和收尾状态。

失败回退：未发布时可关闭 routing prop 回到原 memory 模式，并保留原始问题证据；已发布缺陷通过 patch 修复，不覆盖旧 tag。关闭同步后的外部链接与刷新行为变化必须说明，不能继续宣称深链有效。

完成定义是实现、公开文档、声明类型、正式包与浏览器行为一致；URL、页面、历史和生命周期分别有实际断言。已提交代码或构建成功不代表此功能完整验收。
