### 3.3 启动器必须从进程创建时持续监督

### 5.1 全量测试的硬性定义：打开页面不算行为验收

本任务要求逐项执行完整测试，不是随机点几个按钮或浏览首页。以下结果只能算准备检查，不能单独标为功能 PASS：服务端口在线、HTTP 200、页面打开、菜单出现、截图看起来正常、构建成功、控制台没有报错、按钮存在、doctor 通过。

每条行为用例必须写出并执行：**前置状态 → 具体输入/操作 → 预期结果 → 实际断言 → 清理或恢复 → 证据**。例如远程计数器不能只证明“按钮出现”，要操作并断言数值变化；会话切换不能只证明“姓名变化”，要核对旧实例卸载、新实例挂载及数据隔离；导航不能只核对地址，要核对 URL、业务内容和刷新恢复一致。

自动化需要真实断言，断言失败必须让执行失败。禁止只有 goto、click、sleep、screenshot 而没有结果断言的脚本被计入通过数量。人工验收逐步记录输入和实际结果，并保留关键证据；截图是辅助证据，不能代替未执行的行为。等待应基于页面/请求/状态条件，并设合理超时，不能延长 sleep 直到脚本不报错。

## 8. MESZC 与 demes5.5 全量业务验收

对库存中的每个业务页面，在 dev 和生产分别执行它实际具备的主要操作，不能仅做一次导航巡检：

- 表单/详情：核对同一记录的字段回显，切换不同记录防止旧数据残留，必填和格式校验、取消/关闭/再次进入、loading 结束及错误提示。对保存等操作重点验证前端调用、联邦挂载/生命周期、状态和错误恢复；可用后端允许时用可回收测试数据验证返回后的前端状态。后端持久化、SQL 和业务规则正确性不列入本任务完成门槛，不改真实业务记录。
- Tab/步骤/树/设计器：逐项切换，核对当前选中状态、各区域实际内容和关联数据；对实际支持的编辑、选择、预览、保存等操作验证结果，不能只证明 Tab 标签存在。
- 跨页面：菜单连点、详情深链、修改后返回、请求未完成时切页、权限允许/拒绝、会话切换，以及当前页面支持的导入/导出/附件等功能。

这是插件在真实业务应用中的完整使用验收，后端业务验收明确排除。页面受缺失接口或数据影响时，使用现有可用记录、可回收测试数据，或在本轮副本/独立测试工程中设置符合接口契约的受控响应，继续验证同一组件的挂载、路由、会话、异步返回、表单交互和失败恢复。标明真实后端与受控响应各自的证据来源，不宣称替身证明了真实后端业务正确性。接口替身只在测试条件下启用，不能作为正式默认配置发布，也不能把 8662 换成一个伪造业务站点。

### 8.2 重复前缀、意外 #/ 与合法 hash

目标低代码页面：

`http://localhost:8662/main/lowcode/lowdev/formDesign`

至少 20 次普通刷新、5 次强制刷新、多次菜单连点、前进后退和从其他页面返回。不能出现 `/main/lowcode/main/lowcode/...`，数据与交互应正常，不能只断言 URL。

history 模式不得自行加 `#/`。但业务合法 hash 不能被删除：在宿主自身页面和桥接子页面分别验证非空 hash，中文/编码 query 与 hash 共存、刷新直达及前进后退都要保留语义。另在独立工程验证真正 hash 路由宿主的兼容，避免为了去掉意外 `#/` 破坏合法模式。

### 8.3 后端问题主动规避，插件问题自主闭环

执行以下分流规则，不能把所有错误混为“阻塞”：

| 发现的问题 | 必须采取的动作 | 是否等待用户决定 |
| --- | --- | --- |
| 已知缺失后端接口、SQL 字段、后端业务逻辑/数据问题 | 确认边界后直接排除后端条目，选可用数据或受控响应继续测插件；保留原始错误态的前端验证 | 不等待，不补后端，不列为待修插件缺陷 |
| 插件运行时、构建、共享协商、桥接、URL 同步缺陷 | 最小复现与修复，必要回归，正式发版，registry 安装后复测，更新 8662 并现场验收 | 不等待，必须完成闭环 |
| CLI、包内模板或包内生成内容缺陷 | 修复与回归，同步文档/包内容，正式发版后重新走公开获取路径验收 | 不等待，必须完成闭环 |
| GitHub 示例脚本、业务副本联邦接入、相关前端生命周期缺陷 | 修复正确责任层，提交公开源码或保留私有补丁，重建部署与复测；影响正式包则同步发版 | 不等待，必须完成闭环 |
| 测试脚本目标/断言错误、安装/缓存/端口/构建环境问题 | 修正测试或隔离环境，保存原始失败，重新跑对应行为和最终全量验证 | 不等待，不能只写成遗留 |

已确认的 `/tab/*` 缺失、thirdLogin SQL 缺列等历史后端问题，接手时核对是否仍适用即可，不重新做一夜后端溯源，不新增后端控制器或修数据库。出现新的后端业务问题，用最少必要证据确认责任后同样处理。前端错误态不崩溃、不无限加载、不误报插件故障的验证仍需执行。

环境问题先做可控同条件复现。依赖漂移、缓存、代理、端口冲突和构建失败不能一句“环境问题”就关闭；能在本轮隔离和修正的继续解决。禁止把已有后端问题反复当成停工理由，也禁止以“后端不管”为由掩盖插件本身的故障。
