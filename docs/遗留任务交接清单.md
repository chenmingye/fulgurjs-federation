### ◆ 遗留 1【最高优先，已定位到行】插件：build 下 `allowNodeModules` 判定漏了双向联邦场景

**根因**：`packages/plugin/src/index.ts` 用
`isPureRemoteBuild = exposes.length > 0 && remotes.length === 0` 决定"依赖包是否进改写管线"。
bpm 为双向联邦加了 `remotes: { 'mes-admin': ... }` 后不再满足该条件 → **build 时 node_modules 里的
依赖（element-plus 等）不进改写管线** → 其 vue 导入未门面化 → 内联本地 vue → prod 双实例 → `'ce'`。

**为什么 dev 通、prod 不通**：dev 侧 post 判定走 `devSharedSelf`（bpm 显式 `true`），与
exposes/remotes 数量无关；build 侧却仍用旧判定，两处语义不一致。

**需改的三处（`packages/plugin/src/index.ts`）**：
- L234-235：`.vue?type=script` build 分支的 `allowNodeModules: exposes>0 && remotes===0`
- L240-241：`isPureRemoteBuild`（喂给 `isTransformableId`）
- L248：`allowNodeModules: isPureRemoteBuild`

**建议改法**：统一为 `state.normalized.devSharedSelf || isPureRemoteBuild`——即"自身源码（含依赖）
是否参与 shared 协商"这一语义，dev/build 共用同一开关，与同文件 L247 的
`rewriteShared: command === 'build' || devSharedSelf` 保持一致。

**验收**：
1. 新增回归单测（双向联邦配置下 `allowNodeModules` 为 true；纯 host 为 false）；
2. `pnpm --dir packages/plugin test`（当前 80/80 必须保持）；
3. **重点**：按新后台前缀重打 prod（先 `rm -rf testbed/demo-app/dist/{main,flowable,lowcode}`，
   再 `pnpm run build`）→ rsync 部署 8662 → 待办页 10 行真实数据、无 `'ce'` 错误；
4. 顺带验证 U-2（lowcode 设计器页 prod 是否可渲染——如果 prod 通了就把 U-2 降级为"仅 dev 限制"）。
