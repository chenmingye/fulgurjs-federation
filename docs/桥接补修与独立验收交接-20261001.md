## 接手顺序

先读取当前 diff，保留原有未提交改动及 URL 同步设计文档。不要 reset/clean 整个工作区。先验收本轮源码候选包，再按授权决定发版。5.3.2 registry 包不包含本轮源码修复，不能用它证明本轮修复成功。

### 共享版本与 CJS

- 补回归：1.x 与 2.x 均就绪，非单例要求 ^1 时同步查询必须返回 1.x；要求 ^2 返回 2.x；没有匹配就绪实例时返回 undefined；不发起加载。
- singleton 的已加载优先、宽松冲突告警、strictVersion 拒绝不兼容实例，以及“选中实例尚未就绪时不擅自换另一个实例”。
- 自定义 resolveShare 返回低版本、返回未在原表中的条目、异步返回；同步查询只复用相同消费条件的成功快照，不执行 hook。注册新插件不能复用旧裁决快照。
- CJS 生成结果包含 strictVersion；宿主原生提供闭包与远程协商路径的实例身份正确。重点确认 React、ReactDOM、jsx-runtime 最终使用同一 React 实例。
- 查询单测通过后仍须验证实际 CJS 消费链；本地 fallback 不应掩盖版本冲突。

### Vite 8 生产运行

- 先运行仓库有效 tsconfig 的类型检查、现有单测及 build 门禁，再重建候选 tarball。
- Vite 5.1/6/7/8 × Vue/React × host/remote，分别记录 dev、production build 和 production browser mounting 三种结论。
- Vite 8 双向桥接必须验证挂载、交互、props、路由、会话切换、卸载重挂、零非预期 console/pageerror。不可仅等待一个 testid 后宣布完成。
- examples 的 Vue 桥接 expose 实际等待 `demo-vue-page`；`App.vue` 的 `demo-vue-counter` 属于独立入口，不能用它判定桥接挂载。React 桥接按钮是 `demo-react-counter`。
- 检查生产 chunk 静态/动态图：provider 不得与 await loadShare 的 consumer 同组，也不得经 re-export 壳反向依赖该 consumer。CJS 垫片必须保持同步求值。
- 分别验证无分组、manualChunks 函数/对象/output 数组、原生 codeSplitting/advancedChunks、双角色 devSharedSelf、纯 remote、eager shared、import:false、相对路径提供模块及多版本依赖。
- 特别核对 Rolldown strictExecutionOrder 对 TLA 循环、远程独立入口副作用和 CJS 导出的影响。若失败，修正实现后重新验收，不将“增加分组”本身当作修复证据。
- 用户设置 codeSplitting:false / inlineDynamicImports / preserveModules 时应得到明确配置错误，不能静默生成空白页面。
- 保留 Vite 6 大型宿主内联 init；不得再全版本改为 side-effect import。失败若确属上游，提供最小复现、版本、对应 issue 与影响范围。

### MES 生产重建

本轮没有修改 SVN 副本，没有改变 8662 部署。依赖漂移只是待验证假设。

1. 按项目约定记录 SVN revision、svn info 和初始 status，使用全新副本；保留正常部署备份，不复用旧 dist。
2. 找到可追溯锁文件与包管理器版本；如果只能取得当前锁文件，应明确它不是历史正常基线。不能重新无冻结安装后宣称已还原原依赖树。
3. 可对每个独立应用使用下列隔离构建脚本。输出父目录应预先存在，输出目录必须不存在。脚本不会运行在源目录中，不会删除已有产物。

```sh
node tools/reproducible-build.mjs --source /绝对路径/应用 --output /绝对路径/临时目录/本次构建 --pnpm-version 精确版本 --out-dir dist
# BPM / lowcode 现有配置使用父目录中的产物目录时，分别指定：
# --out-dir ../dist/flowable
# --out-dir ../dist/lowcode
```

4. 脚本要求 corepack 可用。workspace/link/file 依赖、源码软链接或缺失锁文件会停止；遇到这类工程必须补完整 workspace 的隔离构建方案，不绕过检查。构建脚本本身依赖父目录文件时也须保留完整源布局。
5. 按相同源码、配置、包管理器、依赖锁做插件基线/候选版本 A/B；更新候选包时审查锁文件差异，避免其他依赖同时漂移。记录 manifest、lock、chunk 图与部署目录文件清单，排除部署叠加旧产物。
6. 实际页面验收通过才部署。生产回归需覆盖菜单进入、内容区、按钮、弹窗与数据，不能以菜单存在或零 console 错误替代页面功能验证。不得 SVN commit。

### moduleDesign 后端缺口

工作区没有后端源码，当前未实现以下前端实际调用的 **10 个** `/tab` 接口（旧报告写 9 个需重新核对）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/tab/page` | 模块分页，pageNo/pageSize 查询参数及筛选 body |
| POST | `/tab/save` | 新增模块 |
| PUT | `/tab/update` | 修改模块 |
| DELETE | `/tab/delete` | 删除，body 为 ids |
| POST | `/tab/detail` | 详情，id 查询参数 |
| POST | `/tab/js/save` | 新增增强，现有前端 AES 载荷 |
| PUT | `/tab/js/update` | 修改增强，现有前端 AES 载荷 |
| GET | `/tab/js/detail` | 增强详情 |
| POST | `/tab/js/unlock/{moduleId}` | 解锁，type 查询参数 |
| GET | `/tab/get/web-config` | 运行配置，tabId 查询参数 |

必须取得 cku-mes-boot 源码、现有实体/表结构、权限与加解密契约，再补控制器和真实持久化逻辑。不能造一个返回空数据的控制器冒充完成，也不能把 `/group/tab/*` 当作模块接口替换。还需核对分组 update/delete 的真实支持情况。最终验收应完成新增→查询→编辑→详情→增强→运行配置→删除全链路。
