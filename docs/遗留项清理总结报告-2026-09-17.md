## 一、逐项结论

### A.【第一优先】06 流程详情 AMIS 表单区 iframe 通道 —— ✅ 修复，双环境验收绿

**两个叠加根因**（执行文档预判的「时序问题」不成立，实际更严重）：

1. **第三次重拷丢失联邦挂载点**：当前 `detail/index.vue` 是 svn 原版（8 月 25 日字节），
   AMIS/CUSTOM 分支只有乾坤 iframe 通道（`mainAppProps.baseUrl + '/AmisFormRouterPage'`），
   执行文档描述的 isFederatedRealm 分支是旧 testbed 已删代码——文档「已排查事实」基于
   已不存在的代码。
2. **bpm remotes 误用 `name@url` 对象形式**：`{ dev: 'demo-host@http://...' }`——
   插件的 name@ 前缀剥离只支持字符串 external 形式（options.ts:209），对象形式整串
   被当 URL 拼出非法模块 specifier（`demo-host@http://.../@fulgur-entry.js`），
   loadRemote 必失败。

**修**：① detail 双分支重新实现联邦直渲染（`loadRemote('demo-host/AmisFormRouterPage')`/
`FormRouterPage` + `<component :is>` + `:form-params` 单对象透传 + iframe 兜底），realm 判定
实时读 `globalThis.__FULGUR_RUNTIME__`（不做一次性捕获，规避时序争议）；② remotes 改裸 URL
`{ dev: 'http://localhost:8773/main', prod: '/main' }`（键名=注册名）。

**验收**：amis-dev-verify dev/prod 双绿（iframe=0、AMIS 标题+字段直渲染、零错误）；
矩阵 06 dev+prod iframe=0。

### B. dev 07 审批操作页 pageerror —— ✅ 修复，双环境验收绿

**根因**：expose 表把 `./pages/bpm/manager/action` 挂到**子组件**
`ProcessDefinitionDetail.vue`（`props.selectProcessDefinition.name` 无父页传值 → 模板第 13 行
render 抛 `Cannot read properties of undefined (reading 'name')`）；而 bpm 原路由
（remaining.ts 注释保留）用的是**独立页** `ProcessDefinitionDetailMaster.vue`（自带
`processsKey` URL query 拉取逻辑，联邦宿主 URL 天然带该 query）。prod 旧记录「无 pageerror」
只是 Vue 生产版 render 错误走 console.error 不 rethrow——页面同为空壳（148 字符）。

**修**：expose 改指 Master 版（vite.config.ts，含注释说明两者差异）。

**验收**：dev 07 零 pageerror/console.error、textLen 205（「流程：请个假审批流程」+ 时间线 +
操作按钮 + 常用人员区）；prod 矩阵 07 iframe=0 零错 pass。
