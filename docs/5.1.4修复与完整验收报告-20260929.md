## 2. 插件修复

### 2.1 TypeScript 配置继承和声明生成

原实现把 `extends` 当作字符串，数组继承会异常；目录形式引用、父配置声明的 `baseUrl`、`paths`、`include` 和不同应用配置的冲突判断也不完整。

修改 `packages/plugin/src/dts.ts`：

- 支持字符串和数组 `extends`，数组从左至右合并，子配置最后覆盖。
- 配置引用支持目录中的 `tsconfig.json`、无扩展名路径及可解析的包配置。
- `baseUrl` 相对于声明它的配置目录解析；`paths` 保留自己的声明来源，不依赖偶然的遍历顺序。
- 继承的 `include`、`exclude`、`files` 相对于原配置归一化；`references` 按 TypeScript 语义不继承。
- 循环、无效配置和过深继承保留降级路径。
- 多个实际应用配置的别名语义不一致时，保留宽松 ambient 声明并给出中文对齐提示，不因为其中一份可解析就全局删除兜底。

增加 5 项有意义的回归验证，其中 4 项在修复前失败。更新中英文相关文档。

### 2.2 生命周期错误的原始原因

`FgError` 支持 `ErrorOptions`；setup/onSession 包装错误时保留原始 `cause`。实际执行抛错钩子验证 MFU-012、阶段、原始异常以及修复后的重试。成功的 setup 不因后续 onSession 重试而重复执行。

### 2.3 React 契约和测试补齐

新增可复用的 dev/prod 契约测试，覆盖实例独立、宿主重渲染保持局部状态、慢 A 请求与快 B 请求竞态、卸载中的请求、错误后重试、Vue/React 暴露 TS 数据互调，以及 setup/onSession 真实抛错和会话去重。

生产环境能执行的行为实际执行；不再把相应契约统一写成 N/A。静态子模块加载失败后的恢复边界另见第 8 节。

## 8. 首轮失败、归因与保留边界

首轮 MES 页面矩阵真实非零退出，原日志保留。第二次生产复验还发生了修改流程页 20 秒等待不足，导致依赖它的复制分支和修改页强刷前置缺失；保留该轮结果，延长实际表单就绪等待后再次串行全量复验，不把前置缺失算通过。开发环境冷启动 Vite 依赖预构建曾返回 504，带来 MFU-001/MFU-012；待预构建稳定后复验。其他误判包括等待数据前测文本长度、审批动作页隐藏表单选择器，以及报表 id 的 URL 编码匹配错误。修正脚本为实际可见控件和精确接口后重新完整执行，不能将首轮改名成通过。

原项目 `/meszc/tab/page` 返回 404，其来源为 lowcode `src/api/design/module/index.ts`，按该具体 URL 和来源单列，不屏蔽所有 404。原有 BPM null initData 时序问题按历史对照记录单列。原项目权限、后台数据问题不作为插件失败，但插件错误仍进入门禁。

以下已明确的能力边界未在本轮扩大实现：

- 生产静态子模块导入失败后，浏览器模块缓存可能保留失败状态，恢复需要整页刷新；不能宣传全部子模块都可原地重试。相应 React prod 用例验证的是这一边界。
- 跨 origin HMR 存在已记录的不稳定性；Vite 5 的历史 overlay 特例仍保留。不能将这两项宣称已根治。
- 本地 MES 接入修改没有进入 SVN 原项目；用户要求测试副本永不提交 SVN。真实业务项目若要采用，应通过用户自己的项目流程迁移。
