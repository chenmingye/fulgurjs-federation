## 1. 本轮验收对象

测试对象是从 SVN **完整重新检出的 `cku-mes-serverless` 工程**，放入 `testbed/mes-zc/`，包含 `cku-mes-admin`、`cku-mes-bpm`、`cku-mes-lowcode` 三个应用。三应用均通过 PNPM 从 npm 公共 registry 安装正式发布的插件；初始版本为 `@fulgurjs/federation@4.0.0`。如本轮修复插件缺陷并发布补丁版，三应用统一升级到该正式版本，以最终安装版本重新执行受影响及完整验收项。不使用 `file:`、`link:`、`workspace:`、本地 tarball 或仓库源码替代。

本轮从零收集证据：不复用任何旧工程的源码、`node_modules`、`dist`、锁文件、截图、浏览器状态或测试 JSON；报告只写本轮实际结果，不附历史通过率、历史截图或旧结论。

SVN 的完整 URL 尚未在本仓库核实。执行时先从可验证的 SVN 工作副本或用户提供的地址取得 URL，记录 `svn info` 的 Repository Root、URL、Revision；不能凭历史文档猜地址。若 `testbed/mes-zc/` 已存在内容，先检查归属和状态，不覆盖或删除用户新改动。

## 3. 迁移完成的静态门禁

1. 三应用均从 npm registry 安装本轮同一个正式版本，核对各自 `package.json`、锁文件 registry 地址与 integrity，以及实际 `node_modules/@fulgurjs/federation/package.json`。不得使用本地包或链接。
2. 应用源码中的运行时 API 均从 `@fulgurjs/federation/runtime` **静态具名导入**。包括宿主桥、页面表、远程 boot、exposes 页面、业务组件；`remoteSchema` 同样使用具名静态导入。Vite 插件继续从包根导入，CLI 配置使用 `/config`。
3. 搜索全部三应用源码、配置、生成类型和 tsconfig：运行中的代码不得引用 `virtual:fulgurjs-api`、`virtual:fulgurjs-runtime`、`@fulgurjs/federation/client` 或旧 `/context`、`/pages`、`/vue` 子路径；tsconfig 不再包含旧 `client` types，旧运行时类型垫片不参与解析。注释也需表达当前用法。
4. 在宿主与 expose 的 Vite 转换结果中确认：宿主 `remoteSchema` 走内部 schema 模块并等候 dev 探针；expose 的其他运行时导入走内部惰性门面。不得只检查源码字符串或模块 HTTP 200。
5. 记录迁移文件列表及 `svn diff --summarize`。只改联邦接入所需文件，保留全新 SVN 的业务原貌。

任何一项不满足时，先定位并修复，再重新核对静态门禁；修复前不能开始页面矩阵，也不能写“测试通过”。

## 4. 执行顺序与验收点

### A. 插件包与负向契约

先核对已发布 npm 包内容与安装结果；再对 release tag 对应的插件源码运行 `packages/plugin` 单测、有效项目配置下的 `typecheck` 与 `typecheck:latest`，以及 `e2e/scripts/pack-smoke.mjs`。核对已发布包的 `/runtime` ESM 导入和类型解析、运行时静态图只有一份内核、`runtime.js` gzip ≤6144B、根入口和 `/config` 的 CJS 解析仍可用。源码测试结果不得代替已发布包的安装与运行结果。

负向断言须分别证明：旧 `virtual:fulgurjs-api` 无法解析；包根不导出 `loadRemote`；`/runtime` 不支持 CJS `require()`；旧 `/client` 类型项给出可读错误。负向样例放隔离 fixture，不污染 MES-ZC 业务源码。

### B. 新 SVN 工程的 dev

按三个应用实际 `.env` 启动 dev 服务，先完成 Vite 冷启动预构建，再浏览器登录。记录启动日志、三端口、manifest、远程入口和实际页面加载情况。检查 `remoteSchema` 的具名导出在启动预热与按需加载两条路径均可用，页面无旧入口解析错误或第二份 Vue/runtime 身份。

逐页执行新工程的 27 个联邦路由（BPM 21、Lowcode 6）：记录路由、标题、关键内容、表格或设计器、网络请求、控制台异常和**本轮新截图**。**空白内容不算通过**；六个 Lowcode 页面逐页核实内容。若新 SVN 原版确有后端/数据限制，标记“阻塞”并附本轮原版对照与接口响应，不写成 27/27。

交互至少覆盖待办办理、流程模型新增/复制/跨页、菜单跳转、低代码设计器 JS/SCSS/预览三个按钮及签署认证弹窗顶层（与其他弹窗比较 z-index）。每项以可见结果或接口结果断言；“按钮存在”或“点击未报错”不能代替业务结果。

发起**本轮自己创建**的流程实例，记录 `processInstanceId` 和 `taskId`：待办接口出现该任务 → 从该行进入详情 → 真正提交审批 → 同一任务从待办消失并进入已办 → 实例状态结束。每一步都由该 ID 的接口结果与页面结果核对，不允许固定 `pass: true`、检查任意历史已办行或只依靠成功提示。

在独立浏览器上下文拦截本轮远程入口请求，验证页面出现 `MFU-001`，解除拦截后重新加载恢复；同时保留正常、故障、恢复三张截图。只注入本轮浏览器网络故障，不停用户已有服务。

### C. 新 SVN 工程的 prod

三个应用从本轮迁移后的源码重新构建，admin 必须执行其 `postBuild`。用本轮独立的 NGINX 实例和端口部署，不覆盖用户现有 8662 站点；核对主应用页面、两个 remoteEntry、两个 manifest 共五个端点及深链刷新。构建产物的 `remoteSchema` 为空表是约定的降级行为，不得误称为 dev 探针结果。

在 prod 重跑与 dev 同一套 27 页、交互、同实例待办闭环和 `MFU-001` 故障恢复。dev 通过不能替代 prod，fixture 通过也不能替代真实 MES-ZC 通过。
