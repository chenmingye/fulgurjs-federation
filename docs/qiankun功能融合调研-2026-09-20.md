# 调研：乾坤（qiankun）功能融合评估——哪些值得搬进 @fulgurjs/federation

> 2026-09-20 调研（用户令）。结论先行：乾坤功能面 16 项，**9 项已有等价或更强实现、4 项与架构
> 哲学冲突明确不搬、3 项值得搬**（保活/骨架屏/空闲预载），1 项文档化即可。乾坤 3.0 至今未发
> 稳定版（多年 beta、2.x 停滞、社区转向 wujie/micro-app）——反向印证本插件路线。

## 一、逐项对照总表

| # | 乾坤功能 | fulgurjs 现状 | 评估 |
|---|---|---|---|
| 1 | HTML entry（import-html-entry 解析子应用 HTML） | 模块级加载 + manifest 精确清单 | 不搬（MF 更精确，HTML 解析是历史包袱） |
| 2 | JS 沙箱（Proxy/快照） | 同 realm 直渲染（无沙箱） | 不搬（架构哲学，见 §三） |
| 3 | 样式隔离（shadow DOM / 选择器重写） | 无（多版本 CSS 靠版本一致） | 不搬（见 §三；乾坤官方文档自认"不是可以无脑使用的方案"） |
| 4 | 生命周期协议（bootstrap/mount/unmount） | 组件即入口 + federatedBoot | 不搬（迁移指南概念映射第一条卖点） |
| 5 | registerMicroApps + activeRule 路由驱动 | fulgurjsPages 路由表 + 宿主 LayoutContent 集成 | 已有（项目侧，且带参数段通配） |

| 7 | props 传值 | **AppContext（0.8.0 方案已定稿）** | 已覆盖 |
| 8 | initGlobalState 推送 | 0.8 不做（考古：乾坤原件推送从未被消费）；0.9 预留订阅 | 已覆盖 |

| 16 | 子应用独立运行 | dev server / build 产物独立可跑 | 已有 |

## 二、值得搬的 3 项（待用户拍板）

### 候选 A：联邦页面保活（keep-alive）——价值最高

- **痛点**：乾坤社区第一痛点（官方 issue 长期讨论；vivo/知乎多篇工程实践；wujie/micro-app 直接拿保活当核心卖点）。MES 场景刚需：多 tab 切换，表单填一半切走切回丢失。
- **联邦的天然优势**：同 realm + Vue 单例 + 共享组件树——宿主 router-view 的 `<keep-alive>` 可以**直接缓存异步组件实例**，不需要乾坤那套 vnode 缓存/多实例 hide-show hack（乾坤做不动的根因是子应用实例整体销毁；联邦组件级缓存没有这个问题）。
- **实现层**：宿主侧（admin 多 tab 机制 + pages.ts 页面工厂），**插件 runtime 零改动**；可出通用指引/模板。
- **风险**：内存增长（需 include 上限/LRU 策略）；重型组件（vxe-table/表单设计器）缓存成本；状态污染排查难度。建议按页面白名单（meta.keepAlive）而非全量保活。
- **成本**：模板+项目侧 1~2 天 + 全量回归。

### 候选 B：页面加载骨架屏（loader 等价物）——成本最低

- **痛点**：切页/冷启动期间联邦页面区域白屏（dev 预构建窗口 30~60s 尤其明显）；乾坤 registerMicroApps 的 loader 参数就是干这个的。
- **实现**：fulgurjsPageComponent 工厂的 defineAsyncComponent 加 loadingComponent（骨架屏组件），模板层一处改动。**成本：半小时级**。
- **风险**：几乎无。

### 候选 C：空闲预载编排（prefetch:'all' 等价物）

- **痛点**：preloadRemote API 已有但无编排——用户登录后要等首次点开子应用菜单才拉远程 chunk（首开慢）。
- **实现**：bridge 登录后 `requestIdleCallback` 逐个 `preloadRemote(remote, { mode: 'prefetch' })`（低优先级不抢带宽），可配置开关。**成本：小时级**，runtime 零改动（纯模板层编排）。
- **风险**：低（prefetch 模式空闲期执行）。

### 文档化项（不做机制）：页面卸载清理

乾坤 unmount 强制子应用清理 window 级监听；联邦页面 unmount 时这类资源不会自动清（如 context.events.bpm 反向注册的页面级回调、自定义定时器）。Vue `onUnmounted` 本来就能做——**迁移指南加一节"页面卸载清理清单"**即可，不做插件机制（过度设计）。

## 三、明确不搬清单（与架构哲学冲突，写下来防止未来反复）

1. **JS 沙箱**：同 realm 直渲染是本插件核心卖点（window 桥自然可用、无序列化损耗、props 直传实例）。搬沙箱=推翻架构，且收银桶效应：沙箱内 createContext 逃逸面（DOM 事件/定时器/localStorage）qiankun 自己也没堵全。
2. **样式隔离 shadow DOM**：EP/avue 这类组件库弹窗挂 body 直接逃逸 shadow DOM；选择器重写破坏动态类名。乾坤官方文档自认非无脑方案。多版本 CSS 问题继续走「版本一致 + 避坑指南 #9」路线。
3. **HTML entry**：模块级 + manifest 清单比解析 HTML 抓 script 精确得多（CSS/预载都受益），这是 MF 对乾坤的代差优势。
4. **生命周期协议**：组件即入口（零生命周期样板）是迁移卖点，不倒退。

## 四、乾坤现状备注（2026-09 查证）

- qiankun 3.0 仍处于"active development"，多年未发稳定版；2.x 停滞；`umijs/plugin-qiankun` 三年无新版。社区生产环境仍在 2.x，新项目转向 wujie（iframe+webcomponent，保活强）/ micro-app（WebComponent）。对本插件的意义：无沙箱/原生 ESM 路线是社区演进同方向；保活确实是微前端通用痛点（候选 A 的价值背书）。

## 四B、乾坤 3.0 Roadmap 概念评估（Discussion #1378 全文考古）

| v3 规划项 | 内容 | 对本插件的结论 |
|---|---|---|
| Support bundless (Vite) | v3 想原生支持 Vite/ESM | **印证路线**——我们 dev 就是 Vite 原生 ESM 直连，已做到 v3 的目标态 |
| Support Webpack 5 Module Federation | v3 想兼容 MF | **印证路线**——MF 语义是行业方向，我们就是 MF 原生 + 语义对齐 |
| Remove globalState API（breaking change，"provide compatible solution?"） | v3 也想砍 globalState | **印证考古**——推送无人消费；我们的 AppContext + 0.9 预留订阅就是"compatible solution" |
| Deprecate ShadowDOM approach（breaking change） | v3 自己弃 shadow DOM，scoped-style 成默认 | **印证不搬**——§三 的 shadow DOM 排除决定与 v3 演进同向 |
| Standalone Sandbox Module（插件化沙箱，参考 TC39 Realms） | 沙箱拆独立包、可插拔 | 不搬（同 realm 无沙箱是卖点）；"可插拔"理念对本插件无映射需求 |
| Standalone App Loader（streaming/DOMParser） | HTML entry 加载器现代化 | 不搬（manifest 清单比 HTML 解析精确） |
| UI Library Bindings（React MicroApp/MicroAppLink、Vue、Angular） | 框架绑定组件 | **验证 remoteComponent 方向**（./vue 与 MicroApp 同概念）；React 绑定列为远期（`./react`），当前系统纯 Vue 不实现 |
| **Qiankun inspector for Chrome** | Chrome DevTools 扩展查看微前端状态 | **候选 D（值得搬的概念）**：以轻量形式落地——演示页升级为联邦诊断面板（remotes 状态/shared 协商/context 快照/fulgurjs:error 历史日志/远程 chunk 加载耗时），不做浏览器扩展 |
| Support CSP 安全策略 | CSP 下无 eval 执行 | 本插件原生 ESM 无 eval 天然 CSP 友好——README 特性声明一句 + doctor 可选提示（顺手项） |
| Monorepo/UT/E2E/Benchmark 工程化 | 工程配套 | Monorepo/单测/e2e 矩阵已有；性能 benchmark 列为远期可选 |
| 进度 | #1378 下 2021→2023 持续追问"进度如何"，无发布日期 | 佐证：不依赖乾坤演进，自持路线 |

**采纳汇总**：候选 D（诊断面板，替代 inspector）纳入 0.8.0；CSP 声明顺手项；React 绑定/benchmark 记录远期。

## 五、拍板记录（2026-09-20 用户拍板：**A/B/C 全做** + D 随 0.8.0 采纳）

| 候选 | 价值 | 成本 | 结果 |
|---|---|---|---|
| A 保活 | 高（MES 多 tab 刚需） | 1~2 天 + 全量回归 | **做**（meta.keepAlive 白名单 + keep-alive max=8 LRU，默认关闭） |
| B 骨架屏 | 中 | 半小时 | **做** |
| C 空闲预载 | 中 | 小时级 | **做**（登录后 requestIdleCallback prefetch，配置开关默认开） |
| D 诊断面板（源自 v3 inspector 概念） | 中高 | 半天 | **做**（演示页升级，不做浏览器扩展） |
| 卸载清理文档 | 低 | 顺带 | 做（迁移指南加节） |
| CSP 声明 | 低 | 顺带 | 做（README 特性一句） |
| React 绑定 / 性能 benchmark | 远期 | — | 记录不实现 |

执行归属：全部落在**集成器模板/宿主项目侧**（插件 runtime 零改动，gzip 红线不受影响）；已并入 [跨应用传值与方法引用设计方案-2026-09-20.md](跨应用传值与方法引用设计方案-2026-09-20.md) 0.8.0 执行清单。
