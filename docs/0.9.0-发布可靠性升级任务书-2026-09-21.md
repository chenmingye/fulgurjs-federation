**现状**：`packages/plugin` devDeps 的 typescript ^5.8 / vue-tsc 旧版，对最新 EP 类型推断口径与用户 IDE（最新 TS）不一致，曾漏报真实 ts2345。

### 3. dts 类型直连加 `shim` 安静形态

**现状**：`src/dts.ts` 生成的 `types/*.d.ts` 用 `export * from '../../../demo-app-xxx/src/***.vue'` 跨工程直连——VSCode/Volar 打开时以推断项目检查工程外 .vue，满屏"找不到模块 '@/...'"红波浪线（README §9.1-E 靠文档解释，用户被困扰两次）。

**方案**：
1. `federation({ dts })` 选项扩展：`dts: boolean | { dir?: string; mode?: 'source' | 'shim' }`，默认 `mode: 'source'`（行为完全不变）；
2. `mode: 'shim'`：`declare module 'remote-a/X'` 内只生成 `const component: DefineComponent<Record<string, unknown>, Record<string, unknown>, any>` + `export default component`（含 exposes 的 TS 模块如 './api' 生成 `declare module` 内的宽松具名导出 `export const getDictItems: (...args: any[]) => any` 形态）——**不引用跨工程源文件**，IDE 全程干净；放弃 Go-to-definition 直达源码（文档写明取舍）；
3. 单测：dts 生成两种 mode 的产物断言（shim 产物内 0 条跨工程相对路径引用）；
4. 文档：README §1 federation() 选项表 dts 行 + §9.1.5 IDE 说明加一句"根治方案：`dts: { mode: 'shim' }`"；
5. testbed **不改**（保持 source 形态默认值不变）。

**验收**：两种 mode 单测绿；默认行为零变化（source 产物 diff 为空）。

### 6. `PREFETCH_REMOTES` 收编为正式配置面

**现状**：空闲预载名单是集成器模板生成的 bridge.ts 源码常量（`const PREFETCH_REMOTES: string[] = [...]`），改它=改源码。

**方案**：

2. init.ts 生成 T_FULGURJS_BRIDGE 时按该值注入 `PREFETCH_REMOTES` 常量（`false` → `[]`；`string[]` → 原样；`'all'`/缺省 → 全部键）；
3. `init --config` 输出与校验同步（CFG 段新码或不校验均可，倾向宽松不校验、文档说明）；

**验收**：三态（all/partial/false）生成的 bridge 常量正确（单测或临时断言脚本）；testbed 重跑后行为不变。

**方案**：
1. 新增 `packages/plugin/scripts/check-gzip.mjs`：zlib level9 读 `dist/runtime.js`，阈值 **6144 字节**（当前 5231 + 余量；原 5120 已被现实超越，故修正口径）——超限 exit 1；
2. 接入 build 末尾（package.json build 脚本追加 `&& node scripts/check-gzip.mjs`）与 CI；
3. `src/version.ts` 注释改为如实描述："gzip 门禁 ≤6144B（scripts/check-gzip.mjs，0.9.0 实测基线 5231B）"。

**验收**：build 自动执行门禁且通过；注释与门禁一致。
