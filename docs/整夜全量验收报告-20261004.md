### 生产构建配置前提（重要，均为本轮实测结论）
1. **必须停用 `manualChunks` 强制分组**：vite6(rollup) + manualChunks 把 share 门面与 provider 拆成互等 chunk，触发 **TLA 循环死锁**（页面零报错卡加载；实测 `fulgurjs-shared-vue` chunk 顶层 `await loadShare('vue')` 永不返回，环：门面→fallback 预载→provider-vue→门面）。插件源码注释明确"sync 门面仅 rolldown/vite8 使用，rollup 的 chunk 级求值不会互等"——该假设在 manualChunks 强制分组下不成立，**已登记为插件候选改进**（rollup 路径在存在本地副本时也可用 `genBindingFacadeSync`/`genSharedNsFacadeSync`）。`eager: true` 不消除该死锁（实测）。
2. **必须关闭 `sourcemap: 'inline'`**：inline 模式下 vite generateBundle 对超大 chunk 的内联 base64 map 做 replace 爆栈（`vite:build-import-analysis Maximum call stack size exceeded`）。二分证明该崩溃与联邦插件无关（无联邦同配置同样爆栈）。
3. **`vite-plugin-top-level-await` 在 es2022 目标下必须移除**：其 swc(1.15.47) `printSync` 对联邦生成的 chunk 报 `missing field 'type'`；es2015 降级路径又会因 swc 产出 `Legacy octal escape sequences` 而失败。es2022 下 TLA 原生支持，该插件本就无必要。
4. admin 为纯宿主（无 exposes）不产 `fulgurjs-remoteEntry.js`，`dist/main/js/` 下有 `fulgurjs-runtime/provider/shared` chunk 即为正常形态。
5. outDir 在项目根外时 vite 不自动清空，跨配置多轮构建需手动清理，否则 postBuild 统计到脏文件报 ENOENT。
