## 目标

把真实工程中发现的插件顺序、打包器、元数据和运行时问题，转化为可重复的最小用例和自动门禁。每次问题都按同一条路径处理：复现真实组合、缩小用例、修复插件、保留回归测试、在实际浏览器中确认。

本轮重点是防止已知问题类型再次漏到用户工程：

- 第三方 Vite 插件在 federation 改写后注入 shared 导入。
- Rollup/Rolldown 与 `manualChunks` 组合产生共享门面和 TLA 的危险 chunk 依赖。
- dev/prod manifest 的字段被不同消费者按不同含义解释。
- `dts` 根据远端返回值访问本机路径。
- 配置型重试、超时、熔断参数不合法或没有实际生效。
- 用户需要从多个位置导入同一联邦工作流的 API。

不在本方案内：承诺支持所有任意 Vite 插件组合；把具体业务项目的路由、权限或组件注册逻辑写进插件；移除现有公开导入路径；为了覆盖率而穷举完整版本/配置笛卡尔积。

## 实施顺序

### WP1：真实插件链回归用例

**目的**：测试 Vite 真正执行插件钩子的结果，不再仅凭源码字符串判断 post transform 是否存在。

**主要文件**：

- `packages/plugin/tests/build-facade-chunk.test.ts`
- `packages/plugin/tests/transform.test.ts`
- `fixtures/host-vue/package.json`，只加入测试所需依赖
- 必要时新增 `fixtures/host-auto-import/`，不要让通用 host fixture 默认启用 auto-import
- `e2e/tests/dev.spec.ts`，只在需要浏览器行为断言时扩展

**实施步骤**：

1. 新建独立的小型 host 场景：Vue SFC 中直接使用 `ref`，由 `unplugin-auto-import` 注入 `import { ref } from 'vue'`；同一模块同时导入 `loadRemote` 并动态导入一个 remote expose。
2. 分别运行 `vue → auto-import → federation` 和 `vue → federation → auto-import` 两种注册顺序。若 auto-import 固定使用 `enforce: 'post'`，保留一个顺序即可，但测试必须断言最终 Vite 输出确实发生了 post 注入。
3. 通过 Vite 的 `build()` 真实构建，不直接调用 `transformModule()` 代替集成测试。
4. 断言注入的 `vue` 导入经 shared facade 协商；runtime 与 remote 导入都被保留并正常解析；同一文件重复经过 transform 不重复 prepend helper、不二次包装已处理导入。
5. 用最小浏览器用例触发 `ref` 更新并渲染 remote 组件，证明注入的 `ref` 与 remote 使用的是同一 Vue 实例。仅查 bundle 字符串不足以证明运行时实例一致。
6. 保留现有源码契约测试作为快速定位，但不能把它算作该集成用例的替代。

**验收**：上述真实 build 进入常规单测/集成门禁；至少一个浏览器交互断言证明 shared 实例正确；fixture 不修改默认 `fixtures/host-vue` 的现有行为。

### WP5：`dts` 路径边界和 dev CORS

**主要文件**：

- `packages/plugin/src/dts.ts`
- `packages/plugin/src/virtual.ts` 中 dev manifest
- `packages/plugin/src/index.ts` 中 `config()` 和 dev middleware
- `packages/plugin/src/options.ts` 的 `FederationOptions`
- `packages/plugin/tests/dts-shim.test.ts`、`options.test.ts`、`virtual.test.ts`、`doctor.test.ts`

**`dts` 路径实施步骤**：

1. 只接受相对 expose 源路径；拒绝绝对路径、包含 `..` 的路径和空路径。
2. 对 manifest 的 `fsRoot` 和最终 expose 文件调用 `realpath`；用 `relative(root, target)` 检查 target 位于 root 内。对 symlink 指向 root 外的情况也拒绝。
3. 在读取源码或写声明前完成整份 manifest 的字段校验；异常 remote 只跳过自身并输出诊断，不读文件、不生成半截声明。
4. 模块名写入 `.d.ts` 时统一使用合法 TS 字符串序列化，不能直接把远程提供的 `name` 拼进声明代码。
5. 测试用临时目录构造正常路径、`../` 越界、绝对路径、越界 symlink、坏 expose 名和不存在文件；断言越界目标内容未被读取、输出目录没有部分文件。
6. 文档明确：当前 `dts.mode: 'shim'` 仍要读取源码以枚举导出名，所以它不是不可信 manifest 的安全边界。

**CORS / `fsRoot` 实施决策**：

1. 新增 `devCorsOrigins?: string[] | '*'`，并让 `@fulgurjs-entry.js`、dev manifest、Vite 源码请求使用同一来源策略；移除 endpoint 上独立硬编码的 `Access-Control-Allow-Origin: *`。
2. 显式配置的 `server.cors` 必须保留优先级；不允许插件的 endpoint 中间件绕过用户配置。
3. 2.x 先保持未配置时的现有兼容行为，同时当通配 CORS 配合非 loopback host 时警告；提供显式限制来源的方法。评估默认改为 localhost allowlist 的行为变化，若会破坏既有跨机开发，放在下个主版本启用。
4. `fsRoot` 保持 dev-only；新增显式的源码路径暴露开关，2.x 默认值先兼容现状并给出迁移提示，主版本再评估改为 opt-in。不得把它写入 prod manifest。
5. 测试同源/允许来源/拒绝来源/预检 OPTIONS；对 `fsRoot` 断言 dev 与 prod 行为，并验证禁用源码路径后 `dts` 给出明确降级提示。

### WP6：运行时输入和加载容错

**主要文件**：

- `packages/plugin/src/runtime/index.ts`
- `packages/plugin/src/options.ts`
- `packages/plugin/tests/runtime.test.ts`
- `packages/plugin/tests/options.test.ts`
- `packages/plugin/tests/fallback.test.ts`

**实施步骤**：

1. 将 `shareScopeMap`、每个 scope 的 share-key 表和版本表改为无原型字典；对从容器 `init()` 收养的外部对象也用 own-property 判断。保持 `{ scope -> key -> version -> ShareEntry }` 的公开语义。
2. 增加 `__proto__`、`constructor`、`toString` 的 share scope/key 测试；注册和加载后断言 `Object.prototype` 没有新增属性。
3. 对配置期和运行时 `registerRemote()` 统一校验：`timeout` 是有限正数；`retries` 是有明确上限的非负整数；breaker `threshold/resetMs` 是有限正数。错误在运行时注册当场抛出，不留到无限循环。
4. 将 `breaker.threshold/resetMs` 纳入 `RemoteInternal` 并实际用于失败计数和冷却时间；重复注册时覆盖 entry/retry 参数但保留或重置 breaker 状态的规则必须写进测试。
5. 对指数退避设置最大等待值并加入随机抖动；fake timer 测试等待序列和 breaker 开闭行为。
6. 为 remote 的 entry 加载保留单一 in-flight 记录。调用方超时只代表“不再等待”，不能声称浏览器已取消动态 import；超时后下一次调用不得同时重复初始化同一 container。测试慢成功、超时后成功、失败后重试、重复并发调用和 fallback。
7. 对 `remote.promise()` 返回的异步解析也应用 timeout；不能只给 entry 脚本加载加超时，否则 promise remote 仍可能永久 pending。
8. 明确 hook 的错误契约：`beforeLoadRemote` / `afterLoadRemote` 是观测 hook，hook 自身抛错不能把本来成功的模块加载改成失败；`resolveShare` 是决策 hook，显式抛错应向调用方传播，不能静默回退到另一份共享依赖。
9. 错误信息中的 remote URL 去掉用户名、密码和 query 参数；诊断保留 remote 名、origin 和错误码。
10. `preloadRemote('remote/Module')` 按 expose 预载该模块；`preloadRemote('remote')` 保留全 remote 预载。manifest fetch 加超时，URL 按 manifest 契约校验，CSS 只注入选中 expose 的资源。

**验收**：所有坏数值有限时间内失败；配置的 breaker 参数改变测试结果；动态 import 超时语义在文档和类型注释中一致；并发调用不会初始化同一容器两次；模块级 preload 不下载其他 expose。
