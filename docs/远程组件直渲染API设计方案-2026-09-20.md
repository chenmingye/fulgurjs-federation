# 设计方案：远程组件直渲染 API（remoteComponent）+ 集成器模板简化

> 来源：用户评审 detail 页联邦直渲染代码（globalThis 单例 + 手动 try/catch + iframe 旧通道）后拍板方向 B，
> 并质疑 iframe 乾坤旧通道（结论：删除，符合 H3 零兜底铁律与"新插件"定位）。
> 本文为实施方案，**定稿后执行**。

## 一、问题

集成器生成的详情页直渲染代码（bpm detail/index.vue）约 30 行防御式样板：

1. `globalThis.__FULGURJS_RUNTIME__` 全局单例取运行时——**D.1 时代遗迹**（0.4.1 起远程页面可直接静态导入，插件自动惰性单例代理）；
2. 手动 `loadRemote + shallowRef + (mod)?.default ?? mod`——README 已有 `defineAsyncComponent` 标准形态；
3. `isFederatedRealm()` + iframe 旧通道——双轨期产物，与 H3 零兜底冲突。

## 二、方案：`@fulgurjs/federation/vue` 子路径导出 `remoteComponent()`

### API

```ts
// 新增子路径导出（vue 为 peerDependency，不进 runtime.js——保持运行时零框架依赖与 gzip 红线）
import { remoteComponent } from '@fulgurjs/federation/vue'

const FederatedBusinessForm = remoteComponent('demo-host/FormRouterPage')
const FederatedAmisForm = remoteComponent('demo-host/AmisFormRouterPage', {
  loadingComponent: MyLoading,
  errorComponent: MyError,        // 可选；不传时渲染默认错误占位（文案含错误码，显式非静默）
  retries: 2,                     // 透传 loadRemote
})
```

### 语义

- 内部 = `defineAsyncComponent({ loader: () => loadRemote(spec, opts).then(m => m.default ?? m), ... })`；
- **无任何兜底/降级**（H3）：加载失败显式进错误态，runtime 层 `fulgurjs:error` 事件照常发出；
- 模块去重沿用 loadRemote 内部 Promise 缓存（同 spec 不重复加载）；
- 返回标准 Vue 组件，`props`（如 form-params）在使用处透传，不改分发机制。

### 为什么放独立子路径而不是 runtime 本体

runtime.js 是框架无关的（不 import vue），且有 gzip ≤5250 红线守卫；Vue 封装属生态层。
`@fulgurjs/federation/vue` 独立文件、按需引入，runtime 体积零增量。

## 三、集成器模板简化（detail 页）

```ts
// 替换原 30 行样板
import { remoteComponent } from '@fulgurjs/federation/vue'
const FederatedBusinessForm = remoteComponent('demo-host/FormRouterPage')
const FederatedAmisForm = remoteComponent('demo-host/AmisFormRouterPage')
```

- **删除** `isFederatedRealm()` 与 iframe 旧通道分支（含模板 iframe 节点）——用户已拍板（H3 + 新插件定位）；
- 数据就绪分支简化为：设置 federatedXxxParams → 渲染 `<component :is>`。

## 四、删除 iframe 旧通道的后果（需用户定稿确认）

| 场景 | 现状 | 删除后 |
|---|---|---|
| 联邦部署（8662）详情页 | 直渲染 | 直渲染（不变）；加载失败=显式错误占位（原为静默 iframe） |
| 独立访问 bpm 远程页（直开 4527） | iframe 旧通道 | **显式报错**（联邦远程页本就依赖宿主，属非支持场景） |
| 乾坤基线（8661）详情页 | iframe 正常 | **表单区空**——乾坤通道随本变更事实下线（迁移指南 §四 本就计划下线；H6 历史对照已完成使命） |

> 结论：8661 基线从"可用"降级为"仅存档"。若需保留 8661 可用性，须维持双轨（与本变更目的相悖），**默认按删除实施**。
