# 沙箱边界审计（CSS / 全局变量 / 公共依赖）

> 日期 2026-09-16 ｜ 实测脚本 `e2e/sandbox-audit.mjs`、`e2e/sandbox-audit2.mjs` ｜ 环境 dev（admin+bpm+lowcode 三应用联邦）

## 结论

**联邦没有沙箱，也不需要沙箱**——这是与 qiankun 的根本架构差异。qiankun 用 JS Proxy 假 window + 样式隔离做「隔离共存」；@fulgurjs/federation（与 webpack MF 一致）做「**同 realm 共存 + 依赖级隔离**」：所有联邦模块与宿主跑在同一个 window/同一个 CSSOM 里，靠**共享依赖单例协商**防止最大的互扰源（双 Vue 运行时），而不是靠沙箱隔开。

## 实测数据（admin 宿主 + bpm + lowcode 联邦加载前后对比）

### 1. 全局变量（window）

- 联邦加载前后 window 新增键**仅 17 个**，且全部可解释：
  - `mainAppProps`/`mainRouter`：宿主→子应用的桥接对象（对齐乾坤 mainAppProps 语义，by design）
  - `__VUE_I18N_*`/`__INTLIFY_*` 5 个：vue-i18n 的编译期 feature flags（库本身行为）
  - `Prism`/`Sortable`：lowcode 设计器引入的第三方库全局
  - `exports`/`fs`/`stream`/`util`/`chokidar` 等：lowcode 某设计器依赖把 Node 风格 CJS 包装漏到 window（**原版乾坤下同样存在**，属子应用依赖自身的脏行为，与联邦无关）
- 联邦运行时唯一注册面：`window.__FULGURJS_SCOPE__`（值 `['default']`）与 `__FULGURJS_INFO__`——无全局散落
- **未发现子应用覆盖宿主关键全局**

### 2. CSS

- 样式表数量：登录后基线 249 → 联邦加载后 470（+221，子应用页面样式按需注入，**expose chunk 的 CSS 自动加载**，fixtures B-17 用例覆盖）
- `:root --el-color-primary` 基线与加载后均为 `#409eff`——admin(element-plus 2.14.3)/bpm(2.9.1)/lowcode(2.10.2) **三版本 element-plus CSS 共存**，主色变量未被破坏
- 风格主战场：Vue SFC scoped 样式（data-v hash）天然隔离；组件库 CSS 类名前缀（.el-/.avue-/.vxe-）天然分区
- **已知理论边界**：多版本组件库 CSS 同挂 `:root` 变量，后加载覆盖先加载——当前三版本变量值一致故无实际影响；若未来某版本改了变量默认值，以「最后加载为准」，这是同 realm CSSOM 的固有权衡（webpack MF 同样如此）

### 3. 公共方法/依赖实例

| 类别 | 机制 | 实测证据 |
|------|------|---------|
| **shared 键**（vue/pinia/vue-router） | loadShare 协商单例，"已加载优先" | 联邦页面组件与宿主同为一份 Vue（双 Vue 曾致 'ce' 崩溃，修复后全站 0 报错即为单例实证）；pinia/vue-router singleton 冲突警告显示协商发生且取宿主实例 |
| **非 shared 依赖**（lodash-es、axios、avue…） | 各子应用自带副本，模块作用域隔离 | 互不干扰；缺点是体积冗余（联邦的固有权衡） |
| **子应用全局注册**（全局组件/指令/字典） | federatedBoot **显式**注册进宿主 app 实例，失败显式报错（H3） | lowcode 组件数 335→686 的注册面清晰可见 |

## 三、给你的心智模型

| 维度 | qiankun | @fulgurjs/federation |
|------|---------|--------------------|
| JS 运行环境 | Proxy 假 window 沙箱 | **同一 window，无沙箱** |
| CSS | 可选严格隔离/重写 scoped | **同一 CSSOM，无隔离**（靠 scoped 样式+类名前缀+依赖版本对齐） |
| 公共依赖 | 子应用各自打包（或 externals） | **shared 单例协商**（更强：运行时版本协商+双版本共存） |
| 适用代价 | 隔离带来适配成本（全局桥、样式穿透、性能损耗） | 无沙箱要求依赖收敛（本案例已全量验证） |

**一句话**：联邦不做"防你犯错的隔离"，做"让你们共享一切的编排"。全局变量要按团队约定加前缀；全局样式要 scoped 或带业务前缀；这三条纪律在 testbed 真实工程里已全部落实并实测无互扰。
