## 3. admin 生产构建阻塞：归因与修复（8662 部署前提）

**根因（项目侧，两条叠加，均与联邦无关——A/B 干净对照证明）：**

1. 项目原配置 `sourcemap: 'inline'`：r158515 起业务代码使单 chunk 达 38MB 级，`vite:build-import-analysis` 内 convert-source-map 的 `mapFileCommentRegex` 正则回溯栈溢出（Maximum call stack size exceeded）。
2. 工程自带 `vite-plugin-top-level-await@1.6.0` + @swc/core：巨 chunk 使 `printSync` 必崩（missing field type / invalid type: null；@swc/core 1.7.42/1.13.5/1.15.47/1.16.12 全崩，DynamicImport-only 跳过补丁不能根治——真实含 TLA 的 chunk 也崩）。

**本地修复（mes-zc 测试副本，均已验证）：**

- `target: es2015→es2022`（联邦门面 TLA 要求）、`sourcemap: false`、移除 chunk-dumper 调试残留
- 移除 topLevelAwait 插件调用；**移除全部手动 manualChunks**——多组手动 vendor 间存在模块循环，历史靠 __tla 包装顺序化；移除后 rollup 默认分组无循环 chunk。保留手写 `fulgurjs-vendor` 或合并单 vendor 组都会在**运行时**崩（`Cannot access 'defineComponent' before initialization`，本轮实测两种变体并回退）
- `build/vite/plugin/index.ts`：topLevelAwait 引入与调用移除（附回退说明）
- `pnpm-workspace.yaml` 接线 `patches/vite-plugin-top-level-await@1.6.0.patch`（如需回退 es2015 构建的前置）
- `server.origin` 跟随 `VITE_PORT`（bpm/lowcode 原硬编码乾坤时代 4527/4664 → SVG 资源 ERR_CONNECTION_REFUSED）

最终 admin 生产构建（es2022 + 无 TLA 插件 + 无 manualChunks + sourcemap off + @fulgurjs/federation@5.2.5）**exit 0 含 postBuild**，8662 实测运行正确。
