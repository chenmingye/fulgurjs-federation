## 0. 用户验证方法论（永久有效，写入执行前提）

用户每次要求**从 svn 原项目全新重拷 testbed、重新联邦集成、旧截图全部删除后全量重拍**——
这是有意的测试策略：以"首次使用者视角"反复重建，持续暴露隐藏问题。本档将其固化为：

1. 每个执行批次开始 = 全新重拷（禁止在旧 testbed 上增量做）；
2. 旧截图（`docs/screenshots/` 全部）执行前删除，证据全部重产（H10：截图即验收、无截图即未测）；
3. 每轮暴露的新问题追加 §1 台账，并映射到整改项。

## 2. 差距分析

### W1 迁移 CLI——消灭手工样板（最大不丝滑项）

- **现状**：接入真实项目需手工编写 10+ 处样板：vite federation 配置（exposes/remotes/shared/
  emptyOutDir）、宿主页面映射表（fulgurPages）、桥（fulgurBridge）、双份 federatedBoot、
  LayoutContent 联邦分支、staticRouter、NGINX conf（no-cache 头+深链回退+垫片）、
  dayjs dev 专用别名等优化配置。全部依赖隐性契约知识（remote 键名=注册名、store 挂宿主
  pinia、expose 挂独立页……见 §3 清单）。testbed 三次重建全手工重写，每次引入新回归。
- **方案方向**：配置驱动的生成器（`fulgur init` 交互式问询：谁是宿主/谁是远程/页面路由表/
  权限体系/部署形态），生成全部样板文件 + vite 配置改写 + NGINX 模板。模板内容 =
  现已验证的最终形态（§3 清单全量编码）。
- **验收**：从 svn 全新拷贝出发，**零手工编辑**用 CLI 完成联邦集成 → 27 页双环境矩阵全绿 +
  截图全量重产；CLI 产物与现 testbed 的 diff 逐项可解释。
- **工作量**：2~3 天（模板提取 1 + 生成器 1 + 全新重拷实测 0.5~1）。

### W2 doctor 体检工具——部署/配置层自动检查

- **现状**：本轮 NGINX immutable 缓存头由用户先撞上才暴露；remoteEntry 可达性、缓存头、
  CORS、签名漂移、端口全部靠人工，插件无感知。
- **方案方向**：`fulgur doctor --base <URL>`（也可 CI 内嵌）。检查项：三应用 remoteEntry/
  manifest 200 且 Cache-Control=no-cache、index.html 缓存头、hash chunk 抽样可达、CORS 头、
  dev 门面签名一致性、emptyOutDir 配置、shared 配置合法性（含 name@ 对象形式误用）、
  版本协商 skew 预演。
- **验收**：对现 8662 全过；故障注入（改回 immutable/删一个 chunk/关一个 dev server）逐项报出
  且文案三段式。
- **工作量**：1~1.5 天。

### W3 U-7 裸门面修复（消潜伏雷）

- **现状**：`genSharedFacade` 的 export*+TLA 在 rolldown 下命名绑定全 undefined
  （docs/UNRESOLVED.md U-7）。当前无存量消费方，但 provider 注册后 loadShare 即炸，
  且无防回归用例。
- **方案**：改枚举式再导出（复用 enumerateCjsExports，同 genSharedNsFacade 形态）；
  新增"provider 注册后 loadShare 命名导出非 undefined"单测；testbed federatedBoot
  临时回退 bare 导入做 prod 实测验证。
- **验收**：单测绿 + testbed bare 导入 prod 正常 + 分页中文不回归。
- **工作量**：0.5 天。

### W4 跨应用全局配置协商（EP locale/size/theme 类的机制化）

- **现状**：跨应用双 EP 副本，全局配置靠两侧手工 `provideGlobalConfig`（分页中文修复）。
  机制不变则每个新用户遇同类问题（size/theme/popup）都得重走三小时排查。
- **方案方向（含待拍板项，见 §4）**：运行时约定式——runtime 新增
  `provideFulgurAppConfig({ locale, size, ... })`，桥在宿主 app 与各远程副本自动注入
  （把本轮手工逻辑收编为机制）；备选构建期声明式 `federation({ appConfig })`（不推荐，
  构建耦合）。
- **验收**：全新重拷 testbed 删除两侧手工注入、改用机制注入，分页中文保持；新增 size 类
  配置跨副本生效。
- **工作量**：1~1.5 天。

### W5 诊断补码（D.5 盲区收口）

- **现状**：26 码只覆盖插件自身生命周期。本轮三坑全绕过：remotes name@ 对象形式（报成
  无关的 MFU-001，靠读源码定位）；expose 误挂子组件（Vue 层崩，插件无感）；部署缓存头
  （W2 管）。
- **方案**：① CFG 码——配置归一化期检测对象值含 `name@` 前缀、shared 非法组合，显式报错
  指向修法；② DEV 码——冷启动预构建窗口提示（联动 W6）；③ expose 目标组件 defineProps
  依赖扫描的启发式告警（可行性中等、需评估误报，可先文档化检查项）；④ 手册 §8 码表同步 +
  check-manual-codes 防漂移。
- **验收**：故障注入各码（对象形式 name@ → CFG 报错明确指出"对象形式不支持 name@ 前缀，
  改键名/字符串形式"）。
- **工作量**：0.5~1 天。

### W6 dev 冷启动体验

- **现状**：清 .vite 后首轮 30~60s 全是 504/'ce' 瞬态，首次使用者观感="开箱即坏"。
- **方案**：与 W5 联动——联邦入口请求在预构建未就绪时返回明确等待提示而非裸 504；
  需评估 vite optimizeDeps 生命周期钩子可行性，无钩子则降级为 doctor/文档提示。
- **验收**：清 .vite 冷启动首访问无裸 504（有等待提示），第二轮起正常。
- **工作量**：1 天（含评估）。

### W7 发布链

- **现状**：本地 tarball + link；npm org 未注册；CI 配置在但未真跑。`npm install` 即用
  的字面前提不成立。
- **方案**：@fulgur org 注册（**需用户账号操作**）→ npm publish 流程 → CI 真跑（单测 +
  fixtures 版本矩阵 + runtime gzip 红线）→ H7 装后实测随版本固化。
- **验收**：干净环境 `npm install @fulgur/federation` 全链可用。
- **工作量**：0.5~1 天（不含 org 注册等待）。

### W8 验证基建补强

- **现状**：matrix 已有内容就绪轮询；但本轮暴露"全新 profile 探针永远遇不到老缓存问题"、
  失败归因靠人工翻日志。
- **方案**：① 新增持久 profile 用例（重部署后旧缓存访问场景，复刻用户踩坑）；②
  full-verify 失败自动归因（失败套件→页面→截图+console 直接给出）；③ 截图重产与
  func-results 联动归档。
- **验收**：注入"immutable 头+重部署"场景 doctor/W8 用例能报出；full-verify 失败时报告
  直接指出根因页面与截图路径。
- **工作量**：0.5~1 天。

## 3. 全新重拷标准流程（每批次执行前提，硬性）

1. **删旧**：删除现 testbed 副本与 `docs/screenshots/` 全部旧截图（用户明确要求：全部重拍，
   禁止沿用旧图）；
2. **拷贝**：svn 原项目（只读，绝不执行 svn 命令，仅文件系统拷贝）→ `testbed/demo-app`；
3. **联邦集成**（W1 就绪后用 CLI 生成，此前按"重建必做清单"手工，清单=全部积累修复项）：
   - admin：fulgurPages 27 页映射（带参路由显式 spec）、fulgurBridge（权限码为 state 数组、
     **EP locale 注入**）、LayoutContent 联邦分支、staticRouter、permission.ts 剔除空路由、
     乾坤门控、`.env.production` COMPRESS=none、emptyOutDir；
   - bpm：exposes（**action=Master 独立页**）、remotes **裸 URL 无 name@ 前缀**、
     federatedBoot 最小注入（permissions Set 通配、store 挂宿主 pinia）、detail 双分支
     联邦直渲染、dayjs 别名 dev 专用、emptyOutDir；
   - lowcode：exposes、federatedBoot（globCom/avue/hasPermi + **深路径 EP locale 注入**）、
     EP shared singleton、dayjs 别名 dev 专用、emptyOutDir；
   - NGINX：remoteEntry/manifest/index.html **no-cache**（严禁 immutable）、深链回退宿主、
     tab/page 诚实垫片；
4. **构建部署**：三应用 prod 构建部署 8662（admin 三件套：sourcemap:false/停用 TLA 插件/
   es2022）；
5. **数据准备**：AMIS 待办实例（amis-seed3 + amis-start，"勿删"实例可能需重造）；
6. **验证**：full-verify 全链 + 截图全量重产（矩阵 54 张+各套件），问题追加 §1 台账。

## 5. 红线继承（全程有效）

svn 原项目只读、绝不执行 svn 命令；git 只本地提交**绝不 push**；验证必须浏览器真实打开+

## 7. 丝滑边界的诚实声明

目标 = "标准路径丝滑（CLI 十分钟接入 + doctor 一键体检 + 报错指路）+ 非标路径有明确报错"。
