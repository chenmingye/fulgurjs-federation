### 0.3 范围与对外承诺

本轮"跨框架桥接"具体指：**Vue 3 宿主嵌入 React 18/19 子应用、React 18/19 宿主嵌入 Vue 3 子应用**，以插件定义的桥接契约整站挂载/卸载，props 快照、会话代次、加载失败恢复、dev 与生产部署均有真实验证。

**明确不做（与 §12 边界声明一致，文档必须写在一起）：**

- 组件级混渲染：Vue 模板里直接渲染 React 组件（veaury 式互转）不做，那是框架桥接库的产品；
- 子应用路由与宿主 URL 同步：v1 子应用用 memory 路由，URL 同步列为后续方向，不在本轮承诺；
- Angular 及其他框架：无适配层、无验证、不承诺；用户可按公开契约自行实现桥接导出，但插件不背书；
- SSR / RSC / Node 端加载、沙箱、CSS 隔离：继续在支持面外。

## 1. 背景与决策记录

当前 5.1.x 的支持面是"Vue 3 与 React 18/19 各自纯项目的浏览器端联邦"，跨框架仅支持纯 TS 模块消费，README §12 明确声明不支持组件级混渲染。webpack MF 生态以 `@module-federation/bridge` 提供"子应用级跨框架嵌入"，是"网上大多数微前端方案"对这一需求的正规答案，本插件缺位。

已拍板决策（不得在实施中推翻）：

1. 目标版本 5.2.0（新增能力的下一个未占用 minor，实施时重查 registry）。
2. 同包新增 `/bridge` 导入点，不建独立 npm 包（理由：vue/react 已是 optional peer、桥接层重度复用运行时内部、单人维护双包是纯负担）。
3. v1 范围 = 双向子应用级嵌入 + 会话代次打通 + dev/prod 双引擎验证；路由同步不做。
4. 组件级混渲染继续不做，§12 边界声明保留并精确化。

本文定型决策已由作者拍板确认（2026-09-29，与上方四项同级生效，实施中不得推翻）：

- **D1 契约式而非组件式**：子应用导出 `mount/unmount` 契约对象，不是裸根组件。理由：① Vue 子应用的 app 级插件（vue-router、pinia）必须在自己 `createApp` 时装配，裸组件表达不了；② 宿主侧工厂因此与子应用框架解耦，两个工厂覆盖全部组合（组件式需要 4 个）；③ 对齐 webpack bridge 与 qiankun 的生态契约（命名裁决依据 #19）。
- **D2 API 命名**：`/bridge` 宿主侧 `createVueBridgeApp`/`createReactBridgeApp`（对齐 `createHostPages`/`createReactHostPages` 先例）；子应用侧 `defineBridgeApp` 在 `/runtime` 与 `/react` 同名双导出（对齐 `remoteComponent` 先例：入口决定框架）。
- **D3 新错误码 MFU-015（桥接契约非法）、MFU-016（桥接挂载失败）**，现用码为 MFU-001~014。
- **D4 体积预算**：`dist/bridge.js` gzip ≤ 4096B（框架外置、zlib level 9）；`dist/runtime.js` ≤ 9216B 红线不动；React 适配器因新增 `defineBridgeApp` 若超出既有 ≤3072B 目标，记录前后值并论证后更新门禁脚本，禁止悄悄放行。

## 2. 生态对照与命名裁决（#19）

| 方案 | 形态 | 与本插件的关系 |
|---|---|---|
| webpack `@module-federation/bridge` | 子应用级跨框架嵌入，mount/unmount 契约 | 直接对标；`/bridge` 命名与契约形态取自该生态共识 |
| qiankun 子应用 | `bootstrap/mount/unmount` 生命周期导出 | 契约思路同源；本插件不做 JS 沙箱与样式隔离，只做联邦传输+挂卸 |
| veaury（React↔Vue 组件互转） | 组件级混渲染 | **明确不对标**，§12 继续声明不支持 |
| micro-app / wujie | web-component / iframe 容器 | 不对标，不进入 README 对照 |

命名裁决：`bridge` 是 webpack 生态已教育过的词，品牌入口 `@fulgurjs/federation/bridge` 与 `/runtime`（Vue）、`/react`（React）并列，三个导入点各管一类浏览器应用形态，符合 #17/#18。

## 3. 契约与目标 API（唯一约定）

### 3.1 导入入口

```text
构建期        @fulgurjs/federation -> dist/index.js（不变）
Vue 子应用    /runtime  -> 现有导出 + defineBridgeApp
React 子应用  /react    -> 现有导出 + defineBridgeApp
桥接宿主      /bridge   -> createVueBridgeApp + createReactBridgeApp + 契约类型（新增）
```

- `/bridge` 为浏览器 ESM 入口，与 `/runtime`、`/react` 同样不承诺 `require()`，不新增 CJS 浏览器入口。
- 不新增 `/bridge/vue`、`/bridge/react` 等子路径为默认形态；若 G2 实测消费侧摇树不净（Vue 宿主产物混入 React 适配代码），允许拆双子路径作为备案，须在报告记录证据与原因。
- 纯 Vue / 纯 React 项目的依赖隔离不受影响：`/runtime` 新增导出不引 React，`/react` 新增导出不引 Vue；导入图测试同步加断言。
- **桥接用户必须同时安装两套框架**（宿主 package.json 含 vue + react + react-dom），shared 双框架 singleton 为强制配置。这是桥接模式的使用合同，README 必须显著写明，且不破坏"纯项目零对方依赖"承诺。

### 3.2 桥接契约 `BridgeApp`

三个入口共享同一类型定义（对消费者从任一入口导入均可）：

```ts
export interface BridgeApp {
  /** 挂载到容器；同一容器重复 mount 未卸载视为契约违例。返回 Promise 时宿主保持 pending 占位 */
  mount(el: HTMLElement, props?: Record<string, unknown>): void | Promise<void>
  /** 卸载该容器上的实例；未知容器为 no-op 并在 dev 下中文提示 */
  unmount(el: HTMLElement): void
}
```

- 契约实现内部状态必须**按容器 el 分键**：同一契约模块被页面多处挂载时各实例互不干扰，这是可测行为不是文档愿景。
- `mount` 抛错或拒绝时，实现方（`defineBridgeApp`）必须尽力清理已创建的 app/root，不留半挂状态；宿主占位转错误态。
- 远程 expose `./bridge` 的模块**默认导出**契约对象；插件校验 `mount/unmount` 均为函数，否则 MFU-015。

### 3.3 子应用侧 `defineBridgeApp`

```ts
// Vue 子应用 src/bridge.ts —— /runtime 导出
import { createApp } from 'vue'
import { createMemoryHistory, createRouter } from 'vue-router'
import { defineBridgeApp } from '@fulgurjs/federation/runtime'
import App from './App.vue'
import { routes } from './routes'

export default defineBridgeApp((props) => {
  const app = createApp(App, props)
  app.use(createRouter({ routes, history: createMemoryHistory() }))
  return app
})
```

```tsx
// React 子应用 src/bridge.tsx —— /react 导出
import { MemoryRouter } from 'react-router'
import { defineBridgeApp } from '@fulgurjs/federation/react'
import App from './App'

export default defineBridgeApp((props) => (
  <MemoryRouter>
    <App {...props} />
  </MemoryRouter>
))
```

- Vue 形态：工厂接收 props 快照、返回已装配完整的 `VueApp`；helper 负责 `app.mount(el)` / `app.unmount()` 与按 el 的实例跟踪。helper 本身零 Vue 运行时导入（纯逻辑），保证 `/runtime` 导入图不漂移。
- React 形态：工厂返回 ReactElement；helper 负责 `createRoot(el).render(...)` / `root.unmount()`。`react-dom/client` 为外部依赖，build external 列表同步；React 18 与 19 的 createRoot 行为都要实测。
- 远程的 `fulgurjs.config.ts` 只需在 exposes 增加一条 `'./bridge': './src/bridge.ts'`；setup/onSession 沿用现有语义，无桥接专用初始化。

### 3.4 宿主侧工厂（`/bridge`）

```ts
// Vue 宿主
import { createVueBridgeApp } from '@fulgurjs/federation/bridge'
const RemoteReactApp = createVueBridgeApp('remote-react/bridge', { retries: 1 })
// <RemoteReactApp :user-id="uid" @on-ready="..." /> —— props 即快照入参

// React 宿主
import { createReactBridgeApp } from '@fulgurjs/federation/bridge'
const RemoteVueApp = createReactBridgeApp('remote-vue/bridge', { fallback: <p>加载中…</p> })
// <RemoteVueApp userId={uid} />
```

| 项 | Vue 宿主（`createVueBridgeApp`） | React 宿主（`createReactBridgeApp`） |
|---|---|---|
| 展示选项 | `loadingComponent?`、`errorComponent?`、`retries?`、`timeout?` —— 与 Vue `remoteComponent` 现行选项同名同义 | `fallback?`、`error?`（节点或 `(error, retry) => ReactNode`）、`retries?`、`timeout?` —— 与 React `remoteComponent` 同名同义 |
| 泛型 | `createVueBridgeApp<P>(spec, options?)`，P 约束 props 快照类型 | 同左，返回 `React.ComponentType<P>` |
| spec | 与 `remoteComponent` 同格式同解析（remotePrefixes/schema/deriveSpec 生效） | 同左 |
| 占位默认 | 内置中文三段式占位（错误码 + 根因 + 修法 + 重试） | 同左 |

不新增同义选项（Vue 不收 `fallback`，React 不收 `loadingComponent`）；不为简单场景强制建配置；非法参数（负数 retries、NaN timeout 等）按现行诊断风格处理。

### 3.5 shared 强制配方（桥接模式）

```ts
// 桥接宿主与桥接子应用双方的 fulgurjs.config.ts
shared: {
  vue: { singleton: true },
  react: { singleton: true },
  'react-dom': { singleton: true },
}
```

README 明确：桥接场景缺 singleton 会导致双框架实例（Invalid hook call、子应用状态分裂），这是使用合同不是插件自动兜底项；插件不识别"桥接模式"自动注入 shared（项目无关原则，规则能自动化才自动化——这里无法可靠自动化，就写成文档规则 + 诊断提示）。

## 4. 精确语义

### 4.1 生命周期链

```text
宿主渲染桥接组件 -> loadRemote('remote/bridge') -> 容器协商 + 可选 setup/onSession
  -> 契约校验（MFU-015） -> contract.mount(el, propsSnapshot)（失败 MFU-016）
  -> 子应用整站运行（内部自管路由/状态）
宿主卸载组件 / spec 相关重挂条件触发 -> contract.unmount(el)
```

### 4.2 props：快照 + 函数引用，非响应式

与 §10 数据语义一致：挂载时对 props 取快照传入；之后的 props 变化**不追踪、不重渲染子应用**。需要变更时由宿主用 `:key` / key 重建组件实例（= 卸载重挂），文档给出该配方。"实时"通道 = 函数引用（每次调用执行宿主最新闭包）。

### 4.3 重挂条件与会话代次

| 触发 | 行为 |
|---|---|
| 首次渲染 | loadRemote + mount |
| 新的非空 `sessionKey` 且组件仍挂载 | `unmount(el)` + 重新 loadRemote 生命周期 + mount（子应用 onSession 随之重跑；对齐 Vue createHostPages 缓存重置语义与 React 5.1.1 同实例重载语义） |
| 登出（sessionKey → undefined） | 不动作；宿主退出流程自行卸载鉴权内容（与页面表现行合同一致） |
| 同会话宿主重渲染 | 不重挂、不重复 loadRemote |
| 用户点击错误占位"重试" | 重建加载尝试（成功缓存经运行时缓存不重复下载）；契约实例重建 |

挂载期间读到新代次的前提是宿主自身重渲染导致桥接组件重渲染——AppContext 不是响应式订阅，这一点与两个既有适配器同语义，文档照实写。

### 4.4 错误边界与跨 root 的真相

- 宿主侧占位只覆盖**加载阶段与挂载阶段**的错误（远程不可达、契约非法、mount 抛错）。
- 子应用挂载后是其自己的框架 root：**宿主的 ErrorBoundary（React）或 errorCaptured（Vue）捕不到跨 root 的子应用内部渲染错误**。这是两个独立 React root / Vue app 的物理事实，不是缺陷。子应用内部错误处理是子应用自己的事（可自建 ErrorBoundary/onErrorCaptured），README 必须写明，禁止宣称"宿主兜底子应用一切错误"。
- loadRemote 的 MFU 错误保留 code/cause 原样透传到占位，不统一包成 UNKNOWN。

### 4.5 多实例与守卫

- 同一 spec 的桥接组件多实例并存：契约按 el 分键，互不干扰（BR 用例）。
- 同一容器未卸载再次 mount：拒绝并按 MFU-016 给出中文根因（容器已被占用）与修法。
- React 宿主 StrictMode 双 effect（mount→cleanup→mount）安全：顺序 unmount/mount 不得产生双实例或残留；不得用"禁用 StrictMode"换通过。
- 卸载后对旧 el 的迟到 mount resolve 不得复活已卸载实例（请求代次守卫，与既有适配器同标准）。

## 5. 运行时、导入图与开发态

### 5.1 内核与导入图

- `dist/runtime.js` 内核**零改动**为首选目标；桥接层经注入 loadRemote 工作（与两个既有适配器同模式），不初始化第二份内核。若实测存在必须修内核的缺陷，修复与 Vue/React 回归成套，不承诺"内核零改动"绑死。
- 目标导入图：`bridge.js -> runtime.js + context/pages + 桥接适配实现`；`vue.js` 增 `defineBridgeApp`（零 React）；`react.js` 增 `defineBridgeApp`（零 Vue，引入 react-dom/client 外部依赖）。
- 摇树验证：Vue 宿主只用 `createVueBridgeApp` 时，页面产物不得含 React 适配实现；反之亦然（BR12）。若主流 bundler 摇不净，走 §3.1 备案拆双子路径。
- 既有守护测试同步更新：`tests/client-types.test.ts` 的 d.ts 批准清单、`tests/runtime-entry-graph.test.ts` 导入图断言加入新导出与 `/bridge` 入口；禁止删旧断言换全绿。

### 5.2 dev 引擎接线（必做项）

- `virtual.ts` 的 dev 门面生成：`/runtime` 与 `/react` 两个导出面各加入 `defineBridgeApp`，dev 下远程源码从各自入口导入可用，不回退 any、不初始化第二内核。
- `transform.ts` 的 `/runtime`、`/react` 识别不变；`./bridge` 是普通 expose，走现有 expose 通道，预期零特殊处理——但必须浏览器实测，不能"应该没问题"。
- dev 双 server 跨源（host dev + 两类 remote dev）沿用现有 dev-cors 机制，桥接场景实测一轮。

### 5.3 dev 类型

`./bridge` expose 的 `.ts`/`.tsx` 走现有 dts 双轨：可达 fsRoot 出精确契约类型（宿主 `createVueBridgeApp` 处错误 spec/用法可编译期暴露至少到契约对象层面），降级出宽松声明可解析。宿主消费 `defineBridgeApp` 返回值的类型在两个子应用入口的 d.ts 里准确导出。

### 5.4 错误码登记

`src/runtime/errors.ts` 登记 MFU-015/016；`scripts/check-manual-codes.mjs`、README 中英错误码表、占位文案三处同步；不冒用语义不同的旧码。
