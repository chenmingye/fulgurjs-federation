## 7. 使用说明（三段）

**① 双方依赖与 shared（桥接宿主 fulgurjs.config.ts）**：宿主安装 `vue + react + react-dom`，`shared: { vue: {singleton:true}, react: {singleton:true}, 'react-dom': {singleton:true} }`；子应用只装并共享自己的框架（Vue 子应用：vue；React 子应用：react+react-dom），路由库列为直接依赖。缺 singleton 是使用违例——同版本可运行、版本分歧将出现难诊断的加载崩溃（BN05 实测）。

**② 子应用导出与宿主导入**：子应用新增 `src/bridge.ts`（或 .tsx）`export default defineBridgeApp((props) => app/element)` 并在 exposes 加 `'./bridge': './src/bridge.ts'`；宿主从 `@fulgurjs/federation/bridge/vue`（Vue 宿主）或 `/bridge/react`（React 宿主）导入工厂——`const RemoteApp = createXxxBridgeApp('remote/bridge', { retries, getContext })` 后当组件使用（完整语义见 README §8.2；可运行最小组合见 `examples/bridge/`）。

**③ props/context 传递、会话与失败恢复**：业务数据放 `appProps`（挂载时浅拷贝快照，函数引用保留原引用；换引用不重挂，重挂用 :key）；登录代次走受控 `sessionKey` prop——换账号顺序「置 null → 等 卸载 → `clearAppContext()` → 新代次」，`getContext` 提供同步纯 getter（桥接层校验后代写 AppContext）；登出置 null 即卸载清空。加载/挂载失败显示中文诊断占位（错误码+根因+修法）：「重试加载」同页重建，「刷新页面重试」穿透浏览器失败缓存；契约非法/生命周期失败/会话矛盾分别对应 MFU-015/016/017。

### 10.2 pinLoadedShare × loadShare 并发边界：确认存在双实例风险并修复（F9）

风险确认（源码级推演 + 确定性回归）：`loadShare` 设置 `entry.loaded = true` 后 `await entry.get()`，等待期间 CJS 垫片可同步执行 `pinLoadedShare` 写入本地实例；getter 完成后原实现直接 `entry.value = instance` 覆盖——同步消费者持 pin 实例、异步消费者持 getter 实例，单例双实例。同窗口还存在：并发 loadShare 重复触发 get()、getter 拒绝后 `loaded` 残留导致「已加载优先」永久偏袒死条目。

修复（`runtime/index.ts` loadShare，三条所有权规则）：

1. **实例 first-wins**：await 期间条目已有 value（pin/fallback/先完成协商）则协商结果让位，全体消费者收敛同一实例；loadShare 返回条目 value 而非本地变量。
2. **条目级 in-flight get**：并发 loadShare 共享同一次 `pendingGet`，getter 恰好调用一次；落定后清除，失败可重新加载。
3. **失败状态恢复**：getter 拒绝且窗口内无 pin 时回滚 `entry.loaded`（修复前死条目永久抢占单例「已加载优先」），失败窗口内已有 pin 则收敛到 pin 实例而非把失败抛给异步消费者。

确定性回归 8 例（可控 Promise 门，`tests/share-selection.test.ts`）：挂起中 pin→getter 完成（不覆盖）、pin 先发生（getter 零调用）、同条目并发 loadShare（getter 恰一次）、getter 拒绝回滚可重试、单例拒绝后已就绪实例按已加载优先胜出、拒绝窗口 pin 收敛、resolveShare+pin 组合（hook 保留、不重复 get）、非单例多版本 pin 不跨条目污染。单元 558 → **566**。
