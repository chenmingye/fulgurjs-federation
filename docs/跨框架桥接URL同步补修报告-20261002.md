# 跨框架桥接 URL 同步补修报告（2026-10-02）

本轮修复独立复核发现的插件缺陷，并补齐对应回归。基线为 master `6b8bed6` / 包版本 5.4.0。本轮修复随 5.4.1 发布；以下结果不代表 npm 上原 5.4.0 已包含修复。范围为插件、接入文档及桥接 fixtures。

## 1. 修复结果

| 问题 | 修复与回归 |
|---|---|
| 子应用 replace 被误报为 push | 直接接管子应用自己的 Router 导航方法，保留 push/replace；Vue push({ replace: true }) 同样保留动作；浏览器断言 replace 不增加历史条目。 |
| 子应用前进后退使用独立 memory 历史 | Vue go/back/forward 与 React 数字 navigate 委托宿主 go；宿主提交后广播确认位置。 |
| React 只 await navigate 就声称成功 | 观察真实 blocker 和实际提交位置；blocked/proceeding 阶段继续等待，reset 返回 cancelled、proceed 提交后返回 committed；canNavigate 为可选提前拒绝。fixture 已移除提前拒绝，实际验证树内 blocker。 |
| 连续请求被忽略或 Promise 挂起（U13） | 内核和子路由均使用串行 Promise 队列；三次重叠请求逐一落定。宿主外部导航、离页、暂停和销毁会作废旧代次的在飞/排队请求。 |
| 同步异常被吞成取消 | Vue ready 不再静默成功，导航异常以 MFU-033 拒绝并保留 cause；队列失败后可以继续使用。广播应用失败会记录诊断，避免未处理拒绝或永久 syncing 锁。 |
| 生命周期清理不完整 | 两端接线可传第三参数 { signal: ctx.signal } 自动 dispose；React dispose 同时清理 memory router；Vue 恢复原始导航方法。React blocker 和本请求的 pending loader 在作废时取消，避免迟到提交。 |
| 初始 Vue 导航与宿主更新竞态 | 初始化与广播应用有顺序屏障；ready 期间换路径以最新宿主位置为准，不回推旧入口；初始重定向使用 replace。 |
| base 和非法目标 | Vue fullPath 已去 history base，不再二次剥离；React basename 按段匹配。根前缀、空段、编码逃逸、非法位置结构被拒绝；合法 query 编码与重复键保留。 |
| Vite 5/6 旧 React 插件 dev 挂载失败 | 补注入 plugin-react 4 要求的 preamble 标志；纯 Vue 不注入 React refresh。新增真实 HTML 转换回归。 |
| React 18/RR6 生产双 React 实例 | 提供包只豁免自引用，跨共享键的 CJS require 使用同步协商；在可能触发 commonjs 提前变换的 resolve 前登记包根，并保护解析期自引用；空作用域同步实例复用 fallback 的登记/版本守卫，后续 provider 保持同一实例。生产矩阵实际复验。 |

接入示例的子目录 blocker 已按逻辑路径判断，避免部署 basename 导致取消策略失效。

## 4. 使用约定

- Vue：等待 connection.ready 后再 app.use(router)；接线传 ctx.signal，或显式调用 dispose。
- React：返回 connection.element（ReactElement），不要返回自行创建 root 的生命周期对象；接线传 ctx.signal，或显式调用 dispose。
- 自定义宿主端口的 navigate 可接收第三参数 { signal }；应在异步提交前复核，已作废时禁止写宿主 URL。旧端口忽略信号时，插件可以作废自身结果，但不能替外部端口撤销其自行执行的历史写入。
- 本轮未操作 MES 后端、SVN、8662 站点或常驻 Nginx；没有宣称完成这些项目的本轮验收。
