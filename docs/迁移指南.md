# 迁移指南：qiankun 微前端 → @fulgurjs/federation

> 本指南以 testbed/demo-app（admin 宿主 + bpm/lowcode 子应用，21+6 页，真实工程）为案例。

## 一、概念映射

| qiankun | @fulgurjs/federation |
|---------|--------------------|
| 主应用 registerMicroApps | 宿主 `federation({ remotes })` |
| 子应用 entry（HTML） | remote entry（dev: `@fulgurjs-entry.js` 中间件 / prod: `fulgurjs-remoteEntry.js`） |
| 子应用生命周期 mount/unmount | 页面级 exposes（组件即入口，无生命周期样板）；启动期初始化 = 远程 `federation({ setup })`（setup/onSession，见三C 节） |
| 主子应用 window 隔离/沙箱 | 无沙箱：同 realm 直渲染（`window.xxx` 全局桥自然可用） |
| props 传递（qiankun 传参） | 组件 props（路由通道 = params+query 合并；弹窗通道 = 显式 v-bind） |
| 公共依赖 externals/主应用共享 | `shared`（singleton 协商，"已加载优先"） |
| `qiankun` 运行时 + single-spa | `@fulgurjs/federation/runtime`（运行时内核 20KB 级，无 single-spa） |

应用代码统一从 `@fulgurjs/federation/runtime` 导入。Vite 配置继续从 `@fulgurjs/federation` 导入插件。升级自 3.x 时，将 `virtual:fulgurjs-api` 替换为物理子路径；`remoteSchema` 仍按具名导入，开发态由插件填充，构建态为空清单。

## 二、迁移步骤（真实案例顺序）

1. **子应用装插件 + exposes**：把原菜单路由表逐页映射为 `exposes`（`./pages/bpm/task/todo` 对应路由 `bpm/task/todo`）。
2. **shared 声明**：vue/pinia/vue-router 设 singleton；**不要**把业务库（element-plus/avue/dayjs 等）放 shared——插件会在预构建与构建期自动处理其内部对 shared 键的引用（UMD/CJS-only 依赖支持）。
3. **宿主装插件 + remotes**：菜单 URL 通道由 `resolveFulgurjsPageFromPath` 按路由表解析 spec（见 `admin/src/qiankun/fulgurjsPages.ts`）。
4. **全局环境迁移**：子应用依赖宿主的全局（用户/字典 store、i18n、全局组件、全局样式）→ 在子应用 `federation({ setup })` 声明初始化入口文件：默认导出 `setup(context)` 应用级执行一次（全局组件/样式/locale），可选具名导出 `onSession(context)` 按宿主 sessionKey 去重同步用户/权限/字典（换账号自动重跑）；宿主正常 `loadRemote` 页面即可，**无需手写「loadRemote 启动器并调用」**；失败必须显式报错（H3，MFU-011~014）。
   > 旧写法（`exposes` 启动器 + 宿主 `bootRemoteOnce` 手动调用）**继续可用**，属兼容形态，新迁移项目请用 `setup`。
5. **路由参数**：页面组件用 `defineProps` 声明参数（id/taskId 等）；宿主路由通道把 params+query 作为 props 传入。
6. **跨应用弹窗**：原 iframe 嵌子应用页 → `fulgurjsPageComponent(spec)` 直渲染 + props（见 FormDetailsModal）；真外链（数据驱动 URL、AMIS 站点）保留 iframe。
7. **公共依赖坑**：
   - 子应用 axios 的响应解包形状要和后端一致（jeecg `{success,result}` vs yudao `{code,data}`）
   - 子应用全局注册（指令/组件）失败必须显式报错，禁止"忽略继续"
   - 修改态表单禁用逻辑、页面门控（currentStep 等）保持原版语义

## 三、验收清单（从本案例提炼）

- [ ] 21+ 页双环境（dev 双 server / prod NGINX）路由级渲染一致
- [ ] 每页写操作闭环（新增/编辑/删除/发布/导出导入/审批）与原版逐项一致
- [ ] 控制台零报错（21 页 × 2 环境）
- [ ] 零 iframe（跨应用页面与弹窗；PDF/外链/数据驱动 URL 除外）
- [ ] 零兜底：联邦不可用显式报错（杀 remote 故障注入）
- [ ] 装后可用：npm pack → 干净项目 dev+prod（e2e/h7-install-test.sh）

> **目录约定说明**：联邦相关产物统一收在 **`src/fulgurjs/`** 一个文件夹（每个应用一份，内附 README 说明归属）——`types/`（插件每次 dev 自动生成的远程 exposes 类型直连，**勿手改**；运行时类型由包的 `/runtime` 子路径直接解析；无 src 布局回退根目录 `.fulgurjs/types/`）与按角色划分的代码子目录：远程应用为 `exposes/`（联邦启动引导 federatedBoot + 供外部加载的组件），宿主应用为 `host/`（桥接 bridge.ts + 页面路由表 pages.ts）。均为迁移工具脚手架约定而非插件要求，可按团队习惯重组，只要 vite `exposes` 映射与调用点跟着改。

## 三B、首次使用避坑清单（真实迁移踩坑实录，全文见仓库 README「避坑指南」节）

| # | 坑 | 症状 | 解法 |
|---|-----|------|------|
| 1 | 插件升级后未清 `.vite` | 页面渲染回旧逻辑 / 门面签名漂移 404 | `rm -rf node_modules/.vite` + 重启 dev + 换浏览器 profile |
| 2 | pnpm 装 tarball 软链断链 | `Cannot find module '@fulgurjs/federation'` | 重新 `pnpm add -D <tgz>` 并验证目录可达 |
| 3 | UMD/CJS 依赖被移出预构建 | dev 裸 CJS 白屏、`Cannot destructure property 'node'` | 放回 `optimizeDeps.include`（插件自动外部化 shared 键） |
| 4 | 给 shared 依赖加 ESM 别名 | 构建期 `xxx.default.extend is not a function` | **build 必删**（prod rollup 双重 interop，2026-09-16 二次定案）；dev 侧若该依赖已移出预构建（如 element-plus），其 CJS 子路径需 dev 专用别名兜住（`command==='serve'` 才注入） |
| 5 | env 同步脚本回写 | 手改的 `.env.*` 被「还原」 | 改同步脚本的源头（如 `.env.backend`） |
| 6 | 项目构建自身 env 缺键 | `Cannot read properties of undefined (reading 'split')`（如 VITE_BUILD_COMPRESS） | 按项目构建要求补齐 env 键 |
| 7 | 登录异步链未完成就断言 | e2e 偶发被弹回登录页 | 等「登录表单消失」而非固定秒数；后台慢链 ≥15s |
| 8 | 多版本组件库 CSS | 后加载覆盖 `:root` 变量 | 主流版本变量一致则无感；升级时留意 |
| 9 | 后端缺端点 | 404/401 资源报错 | 代理/NGINX 层加诚实空响应垫片（不伪造业务数据） |
| 10 | 远程页面（exposes 目标文件）静态导入 `@fulgurjs/federation/runtime` | 直接静态导入 | 插件自动把该导入改写为惰性单例代理——远程页面写法与宿主完全一致（详见下节三B-1） |

### 三B-1、远程页面如何取宿主运行时

exposes 目标文件（被宿主跨源加载的远程页面/组件）**可以直接静态导入**
`@fulgurjs/federation/runtime`——插件自动把远程页面里的该导入改写为**惰性单例代理**：
求值期零副作用、调用期转发页面级运行时单例。宿主与远程写法完全一致，无需区分。

```ts
// 远程页面内，与宿主页面写法完全一致
import { loadRemote } from '@fulgurjs/federation/runtime'
```

组件直渲染推荐用 `@fulgurjs/federation/runtime` 子路径的 `remoteComponent`——
`defineAsyncComponent + loadRemote` 的标准封装，加载失败显式错误占位（错误码+根因+修法），无任何兜底：

```ts
import { remoteComponent } from '@fulgurjs/federation/runtime'
const FederatedBusinessForm = remoteComponent('demo-host/FormRouterPage')
```

`(globalThis as any).__FULGURJS_RUNTIME__` 直取全局单例仅剩"独立访问远程页 vs 联邦加载"的
realm 检测等特殊场景，常规集成无需使用。

## 三C、跨应用传值：AppContext

原 qiankun `props` / `globalState` / `window.*` 裸口子，统一收编为 context 一等公民通道（对标乾坤 props，带类型与错误契约）：

```ts
// 宿主桥（admin/src/fulgurjs/host/bridge.ts）——登录态同步（可多次调用，幂等 merge）
import { provideAppContext, clearAppContext } from '@fulgurjs/federation/runtime'
provideAppContext({
  user, getToken, store, hostApp, locale,   // 只传有真实消费的键（token 一律 getToken() 拉取）
  sessionKey: 's-101-…',              // 非敏感登录代次 ID：每次成功登录/重登生成新值（禁用 token 充当）
  events: { main: mainEvents },       // 方法池：宿主提供 main.*，子应用反向注册 bpm.* / lowcode.*
  // 项目扩展位：自定义键按需自行提供（如 baseUrl）
})
// 退出登录：clearAppContext()（清 context + 作废远程会话信号/onSession 去重）

// 远程初始化（xxx/src/fulgurjs/setup.ts，经 vite federation({ setup }) 声明）——显式校验消费
import { requireAppContext } from '@fulgurjs/federation/runtime'
const { store, user, hostApp } = requireAppContext('store', 'user', 'hostApp')
// 缺键 → [fulgurjs:CC-001]（三段式，指向宿主桥）；独立直开远程页 → [fulgurjs:CC-002]

// 页面读点（替代 window.mainAppProps?.xxx）
import { getAppContext } from '@fulgurjs/federation/runtime'
const dict = getAppContext().events?.main?.getDictItems?.('sex')
```

要点：

- **时序契约**：bridge（provide）→ 远程 setup/onSession（require）→ 页面模块返回；违反即在初始化处显式失败（CC-001 / MFU-013），无静默；
- **数据语义**：传输层快照 + 函数引用，非响应式（与乾坤 props 同语义）。"实时"两通道 = ①函数引用拉取（`getToken()` / `events.main.*` 每次执行宿主最新闭包）②宿主 pinia 共享响应式（`useUserStore(ctx.store)`）；**同页换账号不依赖页面刷新**——宿主重新 provide 最新 context + 新 sessionKey，远程 onSession 检测到新代次自动重跑；
- **嵌套对象（events）是引用共享**：子应用挂属性即时可见（同 realm 直引用）；
- **方法引用两条通道**：高频热路径（token/字典/文件 URL、反向注册）走 context 函数引用；低频/重逻辑跨应用调用走 exposes 方法模块——远程 `src/fulgurjs/exposes/api.ts` 导出纯函数（不挂 Vue 组件），对面 `await loadRemote('remote/api')`；

## 三D、页面卸载清理清单

乾坤 `unmount` 会强制子应用清理 window 级资源；联邦**组件级**卸载不会自动清——以下资源必须在页面组件 `onUnmounted` 里自行摘除，否则切走再切回会重复注册/重复触发：

| 资源 | 清理方式 |
|---|---|
| `context.events.bpm.xxx = fn` 反向注册 | `onUnmounted(() => { delete getAppContext().events?.bpm?.xxx })` |
| `window.addEventListener(...)` | 记住函数引用，`onUnmounted` 里 `removeEventListener` |
| `setInterval` / `setTimeout` | `onUnmounted` 里 `clearInterval` / `clearTimeout` |
| `window.__FULGURJS_INFO__.errors.push(...)` 之外的自挂全局 | 同理显式删除 |

```ts
import { onUnmounted } from 'vue'
const onBpmEvent = (e: unknown) => { /* ... */ }
getAppContext().events!.bpm!.formEvent = onBpmEvent
onUnmounted(() => {
  const events = getAppContext().events
  if (events?.bpm?.formEvent === onBpmEvent) delete events.bpm.formEvent
})
```

> 轻量提醒而非插件机制：绝大多数页面只有数据请求（随组件销毁自然结束），无需任何清理；有上述全局副作用的页面按清单逐项过一遍即可。

## 三E、乾坤融合三件套 + 联邦诊断面板（`fulgurjs init` 模板直接带出）

配置面总览（详细行为与示例见 README §9.1）：

| 能力 | 配置项 | 类型 | 默认值 | 配置位置 |
|---|---|---|---|---|
| 页面保活（多 tab 状态保留） | `keepAlive` | `boolean` | `false` | 页面路由表条目（`src/fulgurjs/host/pages.ts`；集成器项目改 `fulgurjs.config.ts` 后**删已生成产物**重跑 init） |
| 页面加载骨架屏 | —（内置，无配置项） | — | delay 200ms 的骨架占位 | 页面工厂内置（`pages.ts`） |
| 空闲预载 | `host.prefetch`（集成器项目）/ `PREFETCH_REMOTES`（手工项目常量） | `'all' \| string[] \| false` | `'all'`（全部 remotes 键） | `fulgurjs.config.ts` / `bridge.ts` 顶部 |
| 联邦诊断面板 | —（内置页面） | — | 常驻 | 路由 `/fulgurjs-demo`（prod 为 `/main/fulgurjs-demo`） |

```ts
// 保活：按页开启（默认全关——重型组件缓存成本高）
{ route: '/flowable/bpm/task/todo', name: 'BpmTodoTask', title: '待办任务', keepAlive: true }

// 空闲预载三态（bridge.ts）：
const PREFETCH_REMOTES: string[] = ['mes-bpm', 'mes-lowcode'] // 默认：全部
const PREFETCH_REMOTES: string[] = ['mes-bpm']                // 部分
const PREFETCH_REMOTES: string[] = []                         // 关闭
```

边界：保活缓存上限 max=8（LRU）；骨架屏 delay 200ms 防闪、失败走内置错误占位（错误码+根因+修法）；预载失败 MFU-007（fulgurjs:error 事件，不阻断业务）；保活页的 window 级监听/定时器按「三D 清理清单」处理。

**IDE 提示**：`src/fulgurjs/types/*.d.ts` 为插件自动生成的跨工程类型直连（勿手改）——VSCode 打开这些生成物时可能显示大片"找不到模块 '@/...'"（Volar 以推断项目检查工程外 .vue 所致），命令行 `vue-tsc --noEmit` 走本应用 tsconfig 为 0 错误，构建不受影响；升级插件后 context 导入报 ts(2307) 时 `Restart TS Server` 清缓存。

## 四、乾坤下线顺序

1. 联邦模式全量验收（本清单）
2. `QIANKUN_OPEN=false` 固化，保留一个版本周期回滚能力
3. 删除 qiankun 注册层（admin/src/qiankun/apps.ts 等）与 single-spa 依赖
4. 子应用可独立部署 ⇄ 宿主消费双形态长期保留
