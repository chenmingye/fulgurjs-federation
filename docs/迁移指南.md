# 迁移指南：qiankun 微前端 → @fulgurjs/federation

> 本指南以 testbed/demo-app（admin 宿主 + bpm/lowcode 子应用，21+6 页，真实工程）为案例。

## 一、概念映射

| qiankun | @fulgurjs/federation |
|---------|--------------------|
| 主应用 registerMicroApps | 宿主 `federation({ remotes })` |
| 子应用 entry（HTML） | remote entry（dev: `@fulgurjs-entry.js` 中间件 / prod: `fulgurjs-remoteEntry.js`） |
| 子应用生命周期 mount/unmount | 页面级 exposes（组件即入口，无生命周期样板） |
| 主子应用 window 隔离/沙箱 | 无沙箱：同 realm 直渲染（`window.xxx` 全局桥自然可用） |
| props 传递（qiankun 传参） | 组件 props（路由通道 = params+query 合并；弹窗通道 = 显式 v-bind） |
| 公共依赖 externals/主应用共享 | `shared`（singleton 协商，"已加载优先"） |
| `qiankun` 运行时 + single-spa | `virtual:fulgurjs-runtime`（15KB 级，无 single-spa） |

## 二、迁移步骤（真实案例顺序）

1. **子应用装插件 + exposes**：把原菜单路由表逐页映射为 `exposes`（`./pages/bpm/task/todo` 对应路由 `bpm/task/todo`）。
2. **shared 声明**：vue/pinia/vue-router 设 singleton；**不要**把业务库（element-plus/avue/dayjs 等）放 shared——插件会在预构建与构建期自动处理其内部对 shared 键的引用（UMD/CJS-only 依赖支持）。
3. **宿主装插件 + remotes**：菜单 URL 通道由 `resolveFulgurjsPageFromPath` 按路由表解析 spec（见 `admin/src/qiankun/fulgurjsPages.ts`）。
4. **全局环境迁移**：子应用依赖宿主的全局（用户/字典 store、i18n、全局组件）→ 写 `federatedBoot.ts` expose，宿主加载页面前 `bootRemoteOnce` 执行；失败必须显式报错（H3）。
5. **路由参数**：页面组件用 `defineProps` 声明参数（id/taskId 等）；宿主路由通道把 params+query 作为 props 传入。
6. **跨应用弹窗**：原 iframe 嵌子应用页 → `fulgurjsPageComponent(spec)` 直渲染 + props（见 FormDetailsModal）；真外链（数据驱动 URL、AMIS 站点）保留 iframe。
7. **公共依赖坑**：
   - 子应用 axios 的响应解包形状要和后端一致（jeecg `{success,result}` vs yudao `{code,data}`）
   - 子应用全局注册（指令/组件）失败必须显式报错，禁止"忽略继续"
   - 修改态表单禁用逻辑、页面门控（currentStep 等）保持原版语义

## 三、验收清单（从本案例提炼）

- [ ] 21+ 页双环境（dev 双 server / prod NGINX）路由级渲染一致
- [ ] 每页写操作闭环（新增/编辑/删除/发布/导出导入/审批）与原版逐项一致
- [ ] 控制台零报错（21 页 × 2 环境）
- [ ] 零 iframe（跨应用页面与弹窗；PDF/外链/数据驱动 URL 除外）
- [ ] 零兜底：联邦不可用显式报错（杀 remote 故障注入）
- [ ] 装后可用：npm pack → 干净项目 dev+prod（e2e/h7-install-test.sh）

## 三B、首次使用避坑清单（真实迁移踩坑实录，全文见仓库 README「避坑指南」节）

| # | 坑 | 症状 | 解法 |
|---|-----|------|------|
| 1 | 插件升级后未清 `.vite` | 页面渲染回旧逻辑 / 门面签名漂移 404 | `rm -rf node_modules/.vite` + 重启 dev + 换浏览器 profile |
| 2 | pnpm 装 tarball 软链断链 | `Cannot find module '@fulgurjs/federation'` | 重新 `pnpm add -D <tgz>` 并验证目录可达 |
| 3 | UMD/CJS 依赖被移出预构建 | dev 裸 CJS 白屏、`Cannot destructure property 'node'` | 放回 `optimizeDeps.include`（插件自动外部化 shared 键） |
| 4 | 给 shared 依赖加 ESM 别名 | 构建期 `xxx.default.extend is not a function` | **build 必删**（prod rollup 双重 interop，2026-09-16 二次定案）；dev 侧若该依赖已移出预构建（如 element-plus），其 CJS 子路径需 dev 专用别名兜住（`command==='serve'` 才注入） |
| 5 | env 同步脚本回写 | 手改的 `.env.*` 被「还原」 | 改同步脚本的源头（如 `.env.backend`） |
| 6 | 项目构建自身 env 缺键 | `Cannot read properties of undefined (reading 'split')`（如 VITE_BUILD_COMPRESS） | 按项目构建要求补齐 env 键 |
| 7 | 登录异步链未完成就断言 | e2e 偶发被弹回登录页 | 等「登录表单消失」而非固定秒数；后台慢链 ≥15s |
| 8 | 多版本组件库 CSS | 后加载覆盖 `:root` 变量 | 主流版本变量一致则无感；升级时留意 |
| 9 | 后端缺端点 | 404/401 资源报错 | 代理/NGINX 层加诚实空响应垫片（不伪造业务数据） |
| 10 | 远程页面（exposes 目标文件）静态导入 `virtual:fulgurjs-runtime` | 宿主跨源加载后渲染上下文破坏：resolveComponent / withDirectives / "Missing ref owner" 告警、内容区静默空白 | 改走宿主单例（见下节）；插件 dev 下已对此显式报错拦截 |

### 三B-1、远程页面如何取宿主运行时（跨源单例契约）

exposes 目标文件（被宿主跨源加载的远程页面/组件）**禁止静态 `import 'virtual:fulgurjs-runtime'`**——
该导入会改由远程 dev server 求值，在远程模块图内实例化第二份运行时副本，破坏渲染上下文
（插件 dev 下已对此显式报错，错误信息即指向本节）。

正确写法（二选一，取到的是同一份页面级单例）：

```ts
// ① 直接读全局单例（bpm detail 页先例）
const runtime = (globalThis as any).__FULGURJS_RUNTIME__
const mod = await runtime.loadRemote('host-app/UserProfile')

// ② 经独立产物 getRuntime()（最小宿主/无构建场景，见 manual §5.1）
import { getRuntime, version } from '/fulgurjs-runtime.js'
const mod = await getRuntime().loadRemote('mes-bpm/./TaskCard')
```

运行时单例带 `version` 字段（与插件包版本同源）用于跨源副本一致性诊断；
宿主页面（非 exposes 目标）不受此限，可正常静态导入虚拟模块。

## 四、乾坤下线顺序

1. 联邦模式全量验收（本清单）
2. `QIANKUN_OPEN=false` 固化，保留一个版本周期回滚能力
3. 删除 qiankun 注册层（admin/src/qiankun/apps.ts 等）与 single-spa 依赖
4. 子应用可独立部署 ⇄ 宿主消费双形态长期保留
