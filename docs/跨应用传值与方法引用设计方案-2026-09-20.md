## 一、现状盘点（谁在传什么、走什么口子）

| # | 通道 | 写方 | 读方 | 性质 | 处置 |
|---|---|---|---|---|---|
| 1 | `window.mainAppProps` | admin bridge | bpm 页面 ×5（MainDictTag.vue:95、ProcessInstanceTimeline.vue:194、ProcessInstanceTimelineMaster.vue:202、ProcessInstanceOperationButton.vue:624/:879）、bpm boot（store/user.id） | 业务传值 | **删除**（迁 context） |

| 4 | `provideFulgurjsAppConfig / getFulgurjsAppConfig`（W4） | admin bridge（locale） | 各 boot | ✅ 机制本体 | 升级为 context 存储（旧名 deprecated 别名） |

核心缺陷：同一个"宿主传给子应用的上下文"有 3 个平行口子（#1/#2/#3 与 #4），无类型、无时序契约；方法互调靠 window 裸挂。

## 二、qiankun 概念映射（原件考古结论）

| 乾坤 | 本仓原件事实 | 联邦等价（本方案） |
|---|---|---|
| `props`（mount 期注入） | `getProps()`：data + 函数引用（getToken/store/router/mainEvents…） | **AppContext**（provide 一次，页面级单例） |
| `initGlobalState`/`onGlobalStateChange`（推送） | onGlobalStateChange 回调**为空**——推送从未被消费 | 0.8 不做推送；token 用 `getToken()` 拉取（同乾坤实际用法）；0.9 预留订阅 |
| 子应用暴露方法给宿主 | `window.bpm.formEvent` 裸挂 | context.events 显式注册（迁移） |
| 任意方法跨应用调用 | —（乾坤没有） | **exposes 方法模块** `loadRemote('remote/api')`（MF 增强） |

## 三、数据语义（响应式边界——用户问询后定稿）

**AppContext 是传输层：快照 + 函数引用，非响应式**（与乾坤 props 同语义）。"实时"由三条正规通道承担：

1. **函数引用拉取**：`getToken()` / `events.main.getDictItems(...)` 每次调用执行宿主最新闭包——token 轮换、字典、文件 URL 天然实时；
2. **宿主 pinia 共享响应式**：context.store 把宿主 pinia 实例递给子应用，`useUserStore(ctx.store)` 拿到的就是共享响应式实例（bpm/lowcode 的 user/dict store 现行模式）。数据流：**宿主 → context（传输，快照）→ 子应用 pinia store（响应式）→ 页面自动更新**；
3. **登录态变更**：= 重新登录 = 页面刷新 = bridge 重跑全新 context，无中途推送场景。

明确不做：context 本体不做 Vue reactive（runtime 框架无关 + gzip 红线 + 跨包 proxy 双份陷阱）；若未来出现"context 中途变更需通知"的真场景，0.9 在 context 子路径加 `onAppContextChange` 订阅（独立文件，不碰红线）。

## 四、最终 API（0.8.0）

### 4.1 架构分工（gzip 红线严格不破）

- **`virtual:fulgurjs-runtime`：逻辑零改动**（验收=`packages/plugin/src/runtime/` 目录对 v0.7.1 零 diff；version.ts 版本常量同步 0.8.0 属唯一预期差异，编进 bundle 的常量行随版本走）。旧名 `provideFulgurjsAppConfig/getFulgurjsAppConfig` 保留，client.d.ts 标 `@deprecated` 指向新名；
- **`@fulgurjs/federation/context`（新子路径，~1-2KB 独立文件，与 `./vue` 同模式）**：全部新 API 落在这里，内部经 `globalThis.__FULGURJS_RUNTIME__` 单例读写（provide/get 委托 runtime 既有方法），自持 globalThis 守卫。

### 4.2 context 子路径导出面

```ts
import {
  provideFulgurjsAppContext,   // 宿主写入（merge 语义，幂等可多次）
  getFulgurjsAppContext,       // 读快照
  requireFulgurjsAppContext,   // 显式校验读取（H3）
  type FulgurjsAppContext,
} from '@fulgurjs/federation/context'

// —— 宿主桥（host/bridge.ts）：一次性提供 ——
provideFulgurjsAppContext({
  user, token, getToken, store, hostApp, locale,
  events: { main: mainEvents },            // 事件/方法池（含子应用反向注册位）
  formUrl: ..., baseUrl: ...,              // 项目扩展位（mes 系特定，不进标准表）
})

// —— 远程 boot（exposes/federatedBoot.ts）：显式校验消费 ——
const { store, user, hostApp } = requireFulgurjsAppContext('store', 'user', 'hostApp')
// 缺任一键 → [fulgurjs:CC-001] 三段式抛错（got/expected/example 指向宿主桥），
// 自身未加载运行时（独立直开远程页）→ [fulgurjs:CC-002] 显式
```

### 4.3 FulgurjsAppContext 标准字段表

| 字段 | 类型 | 语义 | 写方 |
|---|---|---|---|
| `user` | `Record<string, any>` | 宿主登录用户原始形态 | 宿主桥（只读约定） |
| `token` | `string \| undefined` | 当前 token 快照 | 宿主桥（只读约定） |
| `getToken` | `() => string \| undefined` | **取最新 token**（拉取式防过期） | 宿主桥（只读约定） |
| `store` | `unknown`（运行时为宿主 pinia） | 子应用 store 挂载/读取宿主共享响应式状态 | 宿主桥（只读约定） |
| `hostApp` | Vue App 实例（同 realm 直引用） | 全局组件/指令注册目标 | 宿主桥（只读约定） |
| `locale` | `unknown` | EP locale 等 UI 配置（原 W4 字段） | 宿主桥（只读约定） |
| `events` | `Record<string, any>` | 事件/方法池：`events.main.*` 宿主提供、`events.bpm.*` bpm 反向注册、`events.lowcode.*` 同理 | 宿主桥建池，子应用挂载 |
| （扩展位） | `[key: string]: unknown` | `formUrl/baseUrl` 等项目自定义键 | 宿主桥；远程 boot 只增不改宿主键 |

变更语义：provide = 顶层 merge（后写覆盖）；约定「宿主先写标准字段，远程只增不改宿主键」；嵌套对象（如 events）是引用共享，子应用挂属性即时可见（同 realm 直引用）。

### 4.4 方法引用（"引用方法"一等公民，两条通道）

| 通道 | 语义 | 适用 | 验收 |
|---|---|---|---|
| **context 携带函数引用** | 同步直调（bridge 先于一切页面加载） | 高频热路径（getToken/getDictItems/getFileAccessHttpUrl）、子应用反向注册（formEvent） | bpm 5 处读取点迁移后矩阵回归 |
| **exposes 方法模块** | `exposes: { './api': './src/fulgurjs/exposes/api.ts' }` → `const { xxx } = await loadRemote('remote/api')` | 低频/重逻辑跨应用调用；任意 expose 任意消费；dts 类型直连自动覆盖 | 最小工程 + testbed 真实收编（见 §六-3） |

规范：`src/fulgurjs/exposes/` 下 `api.ts` 导出纯函数/服务对象（不挂 Vue 组件）；依赖宿主单例的函数（如 defHttp 走 shared）直接写，联邦协商保证同模块图。

### 4.5 错误码

新增 **CC 段**（context）：`CC-001` context 必需字段缺失（三段式，修法指向宿主桥）；`CC-002` 运行时单例不可用（独立直开远程页，修法=经宿主联邦加载）。README 错误码总表同步。

### 4.6 乾坤功能融合三件套（用户拍板全做；全部宿主/模板侧，runtime 零改动）

**A. 联邦页面保活（keep-alive）**——乾坤社区第一痛点（多 tab 切走切回状态丢失），联邦同 realm + Vue 单例反而好做（组件级直接缓存，无需乾坤 vnode hack）：
- 机制：宿主联邦分支外包 `<keep-alive :include="缓存白名单" :max="8">`（max 原生 LRU 防内存失控）；缓存键 = 页面 spec；
- 白名单：`meta.keepAlive` 页面级开关，**默认关闭**（防重型组件 vxe-table/表单设计器缓存成本失控）；
- 执行时先确认宿主 LayoutContent 联邦分支与 vben 自带 keep-alive 的关系，选择正确包裹点；
- 验收：双 tab 实测（A 表单填一半→切 B→回 A 内容还在）+ 切走重载不发生断言 + 截图。

**B. 页面加载骨架屏**——fulgurjsPageComponent 工厂 defineAsyncComponent 增加 `loadingComponent`（轻量骨架组件，delay 200ms 防闪），模板层一处；验收：冷启动切页截图骨架可见。

**C. 空闲预载编排（乾坤 prefetch:'all' 等价物）**——bridge 尾部登录完成后 `requestIdleCallback` 逐个 `preloadRemote(remote, { mode: 'prefetch' })`（低优先级不抢带宽）；配置开关默认开；prefetch 失败走 MFU-007 语义（fulgurjs:error 发出、不阻断业务）；验收：登录后空闲期 network 面板/断言各远程 chunk 已拉取 + 截图。

### 4.7 联邦诊断面板（源自乾坤 v3 inspector 概念，轻量化）

演示页 runtime 信息区升级为完整诊断面板：remotes 状态表（已有）+ shared 协商表（已有）+ **context 快照表（4.6 同轮）** + **fulgurjs:error 历史日志**（window 事件累积+时间戳）+ **远程资源加载耗时**（performance resource entries 过滤 fulgurjs/chunk）。不做浏览器扩展。
